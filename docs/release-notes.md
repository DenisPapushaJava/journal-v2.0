Тестовый выпуск **Journal 2026.1.0-alpha.6**: пакетный импорт, время резки, настройки и улучшения повседневной работы с журналом.

Что нового по сравнению с alpha.5:

- **Время резки** из HTML БЛОК/Wintech и PDF HansLaser сохраняется отдельно от прежних полей заявки. Его можно исправить вручную; оно видно в таблице и добавляется в текст для письма после стоимости. Формат ЧЧ:ММ поддерживает длительность больше суток, секунды округляются вверх до минуты.
- **Пакетный импорт.** Несколько спецификаций открываются отдельными карточками с общими менеджером и заказчиком. Можно добавлять файлы постепенно: второй файл переводит новую заявку в пакет, сохраняя введённые данные. Неподходящие файлы показаны отдельно, включённые заявки сохраняются одной транзакцией. Каждая спецификация получает свою запись и дату из внутреннего заголовка/номера заказа.
- **Замена спецификации при редактировании.** Можно перетащить новый HTML/PDF или выбрать файл, проверить изменения и заменить параметры существующей записи, в том числе при пересчёте для другого станка. Исчезнувшие ID, газ и время очищаются; прежние значения не подставляются автоматически.
- **Проверка перетаскиваемых документов.** Посторонний HTML/PDF не открывает пустую заявку; неподходящий файл и недоступное действие сопровождаются краткой причиной. Неполная распознанная спецификация открывается для ручной проверки.
- **Общие настройки** объединяют оформление, подключение к БД, обновления и диагностику. В «Общие» доступны минимальная цена для письма и персональный цвет новых заявок: частые цвета, палитра, прежний числовой ARGB-код и предпросмотр. Цвет редактора и исторических записей сохраняется; старый `TechnologColor` автоматически не переносится.
- **Таблица:** настройка плотности строк 24–48 px с подходящим размером шрифта, числовая сортировка веса и количества листов, выравнивание чисел вправо, полные значения обрезанного текста в подсказках. Обычный клик выбирает одну строку, чекбокс/Ctrl — набор, Shift — диапазон. Редактирование доступно для одной выбранной заявки; массовые действия используют видимый выбранный набор. Узкие полосы прокрутки больше не перекрывают крайние данные.
- **Результат для письма** заново формируется по текущему выбору, заменяя предыдущий текст. Строки идут от меньшей толщины к большей, затем по материалу; остальные поля сохраняют прежний формат. Копирование передаёт HTML, RTF и обычный текст с выбранным оформлением.
- **Компоновка и темы.** Результат по умолчанию занимает левую половину, команды сгруппированы рядом; при перестановке видны переносимый блок и место вставки. Светлая тема получила мягкие серо-голубые поверхности, обе темы — более читаемые поля, подписи и состояния фокуса. У заставки скруглён общий контейнер; логотип и версия сохранены.
- **Технические отчёты.** При ошибках сохраняется безопасный технический отчёт с кодом JR. Автоотправка в закрытый журнал разработчика включена по умолчанию и отключается в «Настройки → Диагностика»; отчёт можно сохранить в ZIP. Данные заявок, содержимое спецификаций, пути и пароли в отчёт не включаются. Отсутствие интернета не мешает работе: отправка выполняется в фоне с ограниченными повторными попытками.

**Перед первым подключением alpha.6 к Windows MDB сделайте отдельную проверочную копию и закройте другие программы, работающие с ней.** Для времени приложение автоматически подготавливает отдельную таблицу `JournalOrderExtras`; прежние 16 полей `Orders`, прайсы и формат коэффициента не меняются. До подготовки рядом создаётся полная резервная копия `.before-journal-extras-…bak`. Для этого нужен исключительный доступ; при занятости или отсутствии прав журнал остаётся читаемым и показывает причину. Сохранение введённого времени требует успешной подготовки. Подробности — [время резки и совместимость](https://github.com/DenisPapushaJava/journal-v2.0/blob/main/docs/cutting-time.md).

Старая программа не использует таблицу времени. Если она изменит параметры резки, ранее сохранённое время перестанет считаться актуальным до повторного подтверждения. **Проверьте новые операции на копии и откройте её в старой программе** перед переходом на рабочую общую папку. Нативные проверки Jet и установщиков не заменяют проверку старого EXE, двух рабочих ПК и потери сети.

Обновление установленной alpha-версии: **колокольчик → «Получать тестовые версии» → «Проверить обновления» → «Скачать» → «Установить и перезапустить»**. Полный установщик повторно не нужен: зависимости не изменились. Настройки пользователя и внешний файл MDB сохраняются.

Для первой установки Windows — **`Journal-2026.1.0-alpha.6-win-x64-OfflineSetup.exe`**, включающий .NET 10 x64/x86 и модуль MDB x86. Office/Access Runtime не переустанавливаются. **Одобрение SignPath ещё не получено; собственные EXE остаются неподписанными. Smart App Control или корпоративная политика могут блокировать приложение/AccessHost; выпуск не снимает эти ограничения.**

Ограничения: вставка текста из буфера и OCR, автоматический перенос старого конфига, комментарии и создание папок ещё не подключены. Цвет — персональная отметка, отдельного учёта авторства нет. Корзина локальная, не общая резервная копия. На Linux исходная MDB остаётся только для чтения; полная работа доступна в отдельной `.journal-test.json` без обратной записи в MDB. AppImage требует .NET 10 и `mdbtools` отдельно. ZIP предназначен для разработки и не обновляется из программы. Реальные базы и спецификации в поставку не включены.
