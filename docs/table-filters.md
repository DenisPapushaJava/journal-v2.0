# Фильтры, поиск и порядок журнала — UX-55/56/58/60

Локальная реализация 18.10.2026, без push/PR/релиза. Меню с воронкой находится в заголовках «Менеджер», «Вид резки», «Материал», «Толщ., мм», «Гибка» и «Статус». Четыре прежние кнопки статуса над таблицей заменены меню; дата/«Сегодня», поиск и общий «Сбросить» остаются в одной строке. Поиск сжимается по ширине и не переносится.

По последнему уточнению пользователя фильтр заказчика исключён: остаются столбец и обычный поиск по заказчику, без построения большого списка вариантов.

## Поиск по всему журналу — UX-58

По поручению пользователя новый запрос ищет во всём журнале: прежние дата, статус и пять фильтров столбцов сбрасываются, даже если из-за них список пуст. После поиска можно уточнять найденное этими фильтрами. Изменение текста или области поиска начинает новый отбор без прежних ограничений. Изменение только регистра/лишних пробелов сохраняет текущие фильтры. Сортировка и подготовленный текст письма сохраняются; выбор заявок снимается.

Выпадающий список сохранён по последнему уточнению пользователя. Выбранный при реализации компактный состав: **Все поля, Спецификация, БЛЦБ, Заказчик, Менеджер, Материал, Комментарий**. «Все поля» проверяет эти текстовые поля, вид резки и точное числовое значение толщины (запятая/точка). Поиск по дате, статусу, гибке и отдельным числам стоимости/веса/листов в этот список не добавлен: дата и фильтры столбцов остаются отдельными средствами отбора. Служебные поля MDB не являются областью поиска. Неактуальный/недоступный комментарий не используется.

Обычный поиск сравнивает без учёта регистра, каждое слово запроса должно встретиться в заявке. В «Все поля» слова могут находиться в разных полях: `Вахреева 9285`. Выбор «БЛЦБ» ограничивает все слова только этим полем. Символы `*`, `?`, кавычки и прочие знаки — обычный текст, без специального языка запросов. Исходные данные не нормализуются и не меняются.

### Полное совпадение — уточнение пользователя 18.10.2026

По последнему уточнению пользователя поиск оформлен одной рамкой: лупа, список полей, тонкий разделитель, растягивающийся ввод, кнопка **«Точно»** и крестик. Прежний внешний чекбокс заменён как неочевидный. Нативная кнопка-переключатель внутри справа появляется только при конкретном поле, по умолчанию выключена; активность обозначают мягкая заливка и галочка, подсказка — «Полное совпадение». Начало ввода не сдвигается. Общая рамка подсвечивается при работе с элементами/раскрытии списка, клавиатурный фокус кнопок остаётся различимым. Крестик возвращает фокус вводу. Точный режим сравнивает весь запрос с целым значением поля без учёта регистра и крайних пробелов. Внутренние пробелы, ведущие нули и знаки значимы: `9285`, `009285` и `19285` различаются; `ООО Альфа` не равно `ООО  Альфа`. Кавычки не включают режим. Пустой запрос по-прежнему означает отсутствие поискового ограничения.

Смена режима применяет текущий ввод сразу, включая ожидающий debounce, и запускает новый глобальный отбор со сбросом прежних фильтров/выбора. Письмо и сортировка сохраняются. Между конкретными полями режим сохраняется; при выборе «Все поля» выключается и скрывается. Крестик/Escape сохраняют выбранное поле/режим, F5 — также уточняющие фильтры. Общий «Сбросить» возвращает обычный поиск во всех полях и отменяет ожидающий ввод. Режим относится к сеансу, в MDB/пользовательские настройки не записывается. Подпись режима видима, нативная кнопка-переключатель доступна через Tab/пробел; отдельная панель и специальный синтаксис не нужны. Поиск остаётся в одной строке и сжимается по ширине.

### Применение запроса и актуальность данных

Техническое уточнение рамки: у внутреннего `TextBox.search-input` фон/граница прозрачны во всех состояниях. Общие заливки обычных полей в `Inputs.axaml` исключают этот класс: файл подключён после `Journal.axaml` и иначе возвращает прямоугольный фон при фокусе/наведении/блокировке, перекрывая правое скругление пустого поиска. Диагностика обеих тем при 100/125/150/200%: 48 состояний сравнены с рамкой без содержимого, после исправления оба верхних угла совпадают с ней. Исходное перекрытие воспроизведено справа; слева перекрытия не обнаружено. Проверки прозрачности фокуса/наведения/блокировки входят в существующий UI-сценарий; размеры/поиск/данные не меняются.

Проверка этого исправления: 36 целевых Release-тестов окна/поиска/обычных полей заявки/контраста успешны, обе темы. Временный диагностический прогон снимков удалён из исходников; рабочие данные не использовались. Изменение локальное, без push/PR/релиза.

Проверка точного поиска и последней составной компоновки: `scripts/check.sh` — 1111 успешных/16 необязательных пропусков, 20 Python-проверок, Release без предупреждений/ошибок; 66 нативных Access-проверок пропущены на Linux. Проверены сравнение нулей/знаков/пробелов, null, сброс pending-ввода, F5, размещение всех элементов в общей рамке, отсутствие сдвига начала ввода/отдельной рамки TextBox, Tab/пробел, F4/Escape в списке без очистки запроса и возврат фокуса после крестика. Обе темы и 1280×680 при 100/150%, снимки просмотрены. Figma и рабочая MDB не менялись, без push/PR/релиза.

Набор текста отделён от применённого запроса: задержка **300 мс после последнего изменения**, Enter применяет немедленно, смена области применяет текущий ввод немедленно. Пока ввод ожидает применения, снимается выбор строк и недоступны действия с прежними результатами; сам поиск доступен. Крестик/Escape очищают запрос и фильтры сразу, оставляя выбранную область. Общий «Сбросить» также возвращает «Все поля». Отложенный ввод отменяется при сбросе/закрытии/смене модели и не должен появляться повторно. Ctrl+F переводит фокус в поиск.

По UX-59 выбранный день загружается отдельно; первый глобальный поиск/«Все даты» читает историю, затем поиск работает по полному снимку в памяти. F5 перечитывает текущий период, сохраняя запрос/фильтры; при дне прежняя история сбрасывается. Изменения коллег становятся видны после обновления. Запроса к сетевой MDB на каждую букву и непрерывной синхронизации нет. Контракт чтения/ошибок/кэша — [период журнала](journal-period.md).

Запрос готовится один раз, модели строк повторно используются по ID, список заменяется одним уведомлением Reset вместо тысяч отдельных добавлений. Явная очистка нативного выбора нужна и при повторном использовании строк: DataGrid может сохранить их выделение после Reset. Новых зависимостей и изменений MDB нет; отложенная история и операция AccessHost ReadDay добавлены позднее в UX-59 (docs/journal-period.md). Проверки — синтетический снимок из 22 000 записей, поиск из пустого списка, связанные фильтры, F5, выбор, debounce/Enter/Escape/крестик/закрытие и обе темы; это не измерение скорости сетевого Jet на Windows.

Проверка UX-58: `scripts/check.sh` прошёл — Release без предупреждений/ошибок, 1088 успешных тестов/16 необязательных пропусков и 20 Python-проверок. На Linux отдельно пропущены 66 нативных Access-тестов. Снимки поиска/активных фильтров обеих тем просмотрены. Прежние проверки цвета/плотности уточнены для видимых контейнеров: штатный Reset оставляет скрытые строки для повторного использования. Рабочая MDB не использовалась; без push/PR/релиза.

## Выбор и применение

В меню — чекбоксы, «Все» с промежуточным состоянием, «Применить» и «Очистить фильтр». Хотя бы одно значение должно быть выбрано. Изменения черновика не влияют на таблицу до применения; Escape и клик снаружи отменяют их. Текст заголовка сортирует, воронка открывает меню без сортировки. Занятый журнал, смена контекста/источника/личного цвета закрывают открытый черновик.

Значения одного столбца объединяются по **ИЛИ**, столбцы, статус, дата и применённый поиск — по **И**. Новый поисковый запрос сначала снимает прежние ограничения по UX-58 выше. Меню строится по загруженному снимку, с учётом всех ограничений **кроме собственного столбца**: можно расширить его выбор. Число справа — количество подходящих заявок. Выбранные значения без совпадений/исчезнувшие после F5 остаются с нулём, чтобы их можно было снять; обновление данных не сбрасывает их автоматически и не заменяет другими значениями.

В пяти новых меню есть поиск по значениям без учёта регистра: он только скрывает пункты меню, не сбрасывая отмеченные вне поиска. «Все» относится ко всему текущему списку, а не только результатам поиска. Явное включение «Все» снимает ограничение столбца; выбор конкретного единственного доступного значения может закрепить его при последующем снятии соседних фильтров. Применение неизменённого черновика сохраняет прежний набор. Полный выбор всего глобального набора равнозначен отсутствию ограничения.

Текстовые значения группируются без учёта регистра и крайних пробелов; разные марки/названия не склеиваются по похожести. Это только сравнение фильтра, данные не изменяются. Пустые значения — «(Пусто)». Толщины сравниваются как decimal, сортируются численно, выводятся с запятой; неизвестная толщина — отдельное пустое значение. Длинный список имеет ограниченную высоту и общую узкую полосу прокрутки. Длинные названия обрезаются с подсказкой полного текста; подсказки ограничены по ширине и переносятся.

Гибка: «Есть», «Нет», «Неизвестно». Последнее включает недоступные и требующие повторной проверки пометки, отображаемые в строке как «?». Не считать их отсутствием гибки. Отсутствие отдельной пометки при доступных данных по прежнему контракту означает «Нет».

## Обратная связь и сброс

Активные воронки выделяются акцентом. По последнему одобрению пользователя компактные отметки с крестиками находятся в **постоянной общей строке над заголовками таблицы**, вместе с количеством заявок слева и текущим порядком справа. Высота строки 32 px, отметки не переносятся и не сдвигают заголовки. Не поместившиеся фильтры доступны через «Ещё N» в меню с отдельным снятием каждого условия, ограниченной высотой и общей узкой прокруткой. Сам поиск остаётся в одной строке. Одна отметка снимает только свой столбец; она доступна при скрытом столбце/горизонтальной прокрутке. Общий «Сбросить» очищает все шесть фильтров, поиск/его область/точный режим и дату, а также возвращает стандартную сортировку (UX-60).

Применение изменившегося фильтра очищает выбор заявок; неизменённый черновик, отмена и сортировка сохраняют выбор. Готовый результат для письма не меняется. F5/редактирование/массовая смена статуса используют те же ограничения и обновляют доступные варианты при следующем открытии меню. После создания ограничения снимаются, чтобы показать сохранённые строки. По UX-64 выбранный день сохраняется, если все добавленные заявки относятся к нему; иначе показываются «Все даты». Смена источника также сбрасывает фильтры.

## Сортировка даты

### Стандарт по периоду и его сброс — UX-60/64, 18.10.2026

Стандартный состав — **дата → числовой номер спецификации → код**. По UX-64 направление зависит от явного периода: «Все даты» и глобальный поиск — DESC (новые сверху, NULL-дата в конце), «Сегодня» и конкретный день — ASC (поздние номера ниже). Учитываются заголовок/номер спецификации, не момент импорта. Даже если поиск нашёл один день, без выбранной даты это история. Общий «Сбросить» снимает поиск/фильтры/дату и возвращает стандарт истории DESC. Дата после общего сброса — «Все даты», а не период запуска из Общих. Письмо/настройки экрана не меняются; выбор строк очищается по прежнему правилу изменения фильтров.

Для остальных заголовков обычные клики переключают **возрастание → убывание → стандартный порядок**. В стандарте истории первый клик «Даты» выбирает ручной ASC, второй — ручной DESC, третий — стандарт истории DESC. В стандарте дня ASC первый клик выбирает ручной DESC, следующий возвращает стандарт дня ASC. Ручной DESC, совпавший со стандартом истории, остаётся ручным до явного сброса; смена периода его не переворачивает. Стандарт остаётся реальной составной сортировкой с видимой стрелкой. Ctrl+клик и программный Clear сортировок тоже восстанавливают стандарт, не внутренний порядок чтения MDB.

При пользовательской сортировке справа в общей строке над заголовками видна отметка «Порядок: Стоимость ↓ ×», в том числе при скрытом столбце/пустом результате. Крестик снимает только сортировку: дата, запрос/точный режим, фильтры, выбранные заявки и письмо сохраняются. Если фокус был на исчезающей отметке, он возвращается таблице. При стандартном порядке там же постоянно виден текст «Порядок: Дата и номер ↓» для истории или «Порядок: Номер ↑» для дня, без крестика.

Последнее одобренное уточнение пользователя заменяет оба промежуточных варианта — динамическое появление отметки сверху и разнесённые фильтры сверху/сортировку снизу. `TableViewBar` присутствует с открытия окна, сохраняет высоту 32 px при фильтрах/ASC/DESC/сбросе; правая зона порядка имеет постоянную ширину 280 px. `AppliedFilterStrip` измеряет компактные кнопки и помещает остаток в «Ещё N», без переноса и скрытых фокусируемых кнопок. Меню остаётся открытым при снятии одного из нескольких условий, закрывается при исчезновении переполнения или блокировке действий. Escape возвращает фокус кнопке; после снятия последнего условия — оставшимся фильтрам/таблице. По последнему уточнению UX-61 нижняя строка состояния высотой 24 px показывает только обновление/итог последней операции; подпись активной заявки/«Выбрано несколько» удалена по последнему решению пользователя как дублирующая выделение и счётчик массовых команд; прежние две строки занимали 68 px. Кнопка «Диагностика» удалена, раздел остаётся в Настройках. Длинные подписи обрезаются с полным значением в подсказке.

Прежний Shift+клик сохраняет несколько критериев: отметка показывает первый и «+N», подсказка — всю цепочку по приоритету. Модифицированные клики передаются нативному DataGrid; третий шаг относится к обычному клику без модификаторов. Порядок живёт только в сеансе, после запуска снова стандарт.

F5, календарь/«Сегодня»/«Все даты», новый поисковый запрос, крестик поиска/Esc, отдельный сброс фильтра и автоматическое снятие ограничений после создания сохраняют ручной выбранный порядок; стандарт автоматически следует текущему периоду. Внутренние сбросы вызывают `ResetSearch`, а явная общая команда дополнительно запрашивает сброс сортировки. Новая строка подчиняется текущей сортировке, после явного сброса занимает место по дате/номеру.

`Tables/JournalTableSorting` управляет сортировкой представления, отслеживает замену ItemsSource/изменение SortDescriptions и публикует состояние в модель; общий/отдельный сбросы связываются событием. Изменения сортировок группируются через DeferRefresh. Обработчики отключаются при закрытии окна. MDB, исходные поля, сортировка письма и формулы не меняются.

Проверка итоговой компоновки UX-60/61: `scripts/check.sh` — 1145 успешных тестов и 16 необязательных пропусков, 20 Python-проверок; Release без предупреждений/ошибок. Все 67 нативных Access-проверок пропущены на Linux. Отдельно проверены две темы, 100/150%, ширины 1280/1366/1920: постоянные координаты заголовков/высота таблицы при фильтрах и ASC/DESC/сбросе, переполнение/индивидуальное снятие в меню, resize/Escape/пробел/блокировка действий, нижняя строка и длинные значения без перекрытия. Предыдущий отказ минимальной высоты таблицы при настройке высоких панелей устранён компактной нижней строкой; требования теста не ослаблялись. Снимки синтетических данных просмотрены, Figma не изменялась.

После последнего удаления подписи активной заявки (UX-61) пройдены 24 целевые проверки сортировки/выбора/буфера, Debug-сборка успешна. Проверены длинный итог операции с полной подсказкой, постоянная высота таблицы, обе темы при 100/150%; снимки просмотрены.

Уточнение пользователя 18.10.2026 заменяет прежний второй критерий по коду: **дата → номер спецификации с числовым сравнением → код записи только при совпадении даты и номера**. По последующему UX-64 направление ASC действует внутри дня, DESC — для истории. Внутри выбранного дня стандарт — возрастание с видимой стрелкой «Даты»: `859 → 900 → 909 → 920 → 1121`. Все три критерия меняют направление вместе при нажатии на заголовок. Пустая дата идёт перед известными при возрастании, после них при убывании.

Числовые части номера сравниваются по значению, без ограничения Int32 и преобразования в часы/минуты. `0900` и `900` равны для сортировки, поэтому при одинаковом дне их порядок определяет код; исходное написание сохраняется. Ручные/необычные номера также допускаются: текстовые части сравниваются без учёта регистра, числовые — естественным образом (`А-2` до `А-10`), крайние пробелы не влияют на сравнение. Заголовок «Спецификация» использует такое же сравнение номера с кодом при совпадении.

Новая заявка с номером `900` появляется после `859`, новый день — после прежних. Пакет с перемешанными датами/номерами и поздно добавленная ранняя спецификация занимают свои места, а не безусловно конец списка. Сохранённое редактирование также пересортируется. При явно выбранной другой сортировке новые строки следуют ей; добавление не возвращает стандарт принудительно. После перезапуска снова действует стандарт по дате/номеру.

Смена/очистка даты, пустой результат фильтра и F5 сохраняют выбранное направление сортировки. Само нажатие на заголовок сохраняет отмеченные заявки; смена даты очищает выбор по общему правилу. Календарь фильтрует именно день. Время из номера спецификации не извлекается, исходные даты/номера и MDB не меняются.

Сравнение реализовано в Desktop/Tables/SpecificationNumberSortKey, ключи кэшируются в строке таблицы и обновляются вместе с исходным снимком. Сортируется представление DataGrid; инфраструктурные читатели и порядок хранения не меняются. Проверки используют синтетические данные и Avalonia Headless на Linux; нативная Windows отдельно не проверялась.

Проверка этого уточнения 18.10.2026: scripts/check.sh — 1066 успешных/16 необязательных пропусков, 20 Python-проверок, Release без предупреждений/ошибок; отдельно 66 Access-тестов пропущены на Linux. Проверены оба направления, ведущие нули/совпадающие номера/пустые даты, одиночное и пакетное добавление, поздний ранний номер, редактирование, F5, календарь и сохранение ручной сортировки. ## Статус и личный цвет

Без включённой персональной окраски: «Без статуса», «В работе», «Готово», «Отгружено». При включённом «Использовать свой цвет»: **«Мои заявки»** с образцом цвета, «Другие без статуса» и три рабочих статуса. Название выбрано пользователем; «Мой цвет»/«Мои по цвету» не использовать. Статусные категории сохраняются в меню даже при нулевом количестве.

Три рабочих статуса определяются прежними точными кодами Orders.Color. «Мои заявки» — точным совпадением с текущим допустимым персональным ARGB; остальные цвета/NULL/−1 относятся к «Другие без статуса». Без включённого личного цвета все такие строки относятся к «Без статуса». Категории не перекрываются. Смена статуса/цвета может убрать строку из текущего фильтра; отдельной истории авторства нет.

При включении личного цвета выбранное «Без статуса» разделяется на обе новые категории без потери строк. При отключении «Мои заявки» удаляются из выбора; оставшиеся категории сохраняются, выбор только «Мои заявки» сбрасывается на «Все». Поиск, дата и остальные столбцы сохраняются. Недопустимый промежуточный ввод цвета не меняет принятое значение.

## Контекст всплывающих фильтров — 19.10.2026

При разборе Windows-трассы alpha.10 обнаружены шесть ошибок привязки редактора
столбца. Они воспроизведены в журнале Avalonia: `SearchText`, `AllChecked`,
`ToggleAllCommand`, `VisibleOptions`, `HasNoMatches` и `CanApply` временно
получали `OrderColumnFilterViewModel` вместо `ColumnFilterEditorViewModel`.
Аналогичный сценарий подтвердил четыре ошибки редактора статуса. Меню позднее
получало правильный контекст и работало; успешное открытие само по себе не
доказывало отсутствие ошибок.

У обоих popup исходный `DataContext` явно равен null. При подключении заголовка
корневая область получает проверенную модель, а панель редактора — compiled
binding на `Editor` / `StatusFilterEditor`; тип дочерних привязок выводится из
этого свойства. Не назначать контекст редактора только в `Opened`: наследование
может сработать раньше. При смене модели и отсоединении заголовка меню закрывается,
подписка снимается, корневой контекст очищается вместе с контекстом редактора.
`Opened` по-прежнему подготавливает актуальный черновик и переводит фокус,
`Closed` отменяет неприменённые изменения. Запросы к MDB и правила отбора не менялись.

Регрессия — `FilterBindingLifecycleTests`: первое/повторное открытие мышью,
закрытие Escape с возвратом фокуса, отсутствие применения черновика, обе темы
и их смена при открытом меню, пересоздание шаблона, временный null-контекст,
подключение другой модели и отсоединение старой. Проверяется журнал ошибок
привязки внутри popup, включая ошибки, которые Avalonia обрабатывает без
исключения наружу; обработчик журнала восстанавливается после теста.
Используются синтетические данные и Avalonia Headless на Linux; повторная
Windows-трасса остаётся отдельной проверкой. Локально без push/PR/релиза.

Проверка исправления 19.10.2026: прежний код не прошёл все четыре новых
сценария с воспроизведением указанных ошибок привязки. После исправления

## Перечитывание данных — UX-71

F5, кнопка Обновить и автоматическое чтение сохраняют текущие фильтры/поиск/сортировку и выбор по ID; актуальные выбор и положение видимой строки фиксируются перед применением ответа. Сортировка и навигация доступны во время чтения того же контекста, запись ждёт завершения. Если запись изменилась и перестала подходить фильтру, она исключается из выбора с короткой нейтральной отметкой, сосед не выбирается. Смена фильтра/поиска/даты по-прежнему очищает выбор. Удалённый видимый якорь заменяется ближайшим сохранившимся только для прокрутки. Контракт — docs/journal-auto-refresh.md.

## Фаска — 23.10.2026

Колонка «Фаска» использует тот же связанный фильтр «Есть / Нет / Неизвестно»,
что и «Гибка». Неизвестное чтение операций или устаревшая привязка — ?,
не «Нет». Независима от гибки, входит в общую строку активных фильтров и
«Сбросить». Хранение — [дополнительные операции](order-operations.md).
