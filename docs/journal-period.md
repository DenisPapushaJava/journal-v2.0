# Период журнала — UX-59

UX-69 дополняет ручной F5 автоматическим read-only обновлением периода с наблюдением файла и резервной сверкой. Контекст сохраняется, история после фонового чтения дня сбрасывается. Контракт — [journal-auto-refresh.md](journal-auto-refresh.md).

Поручение пользователя 18.10.2026: запуск с сегодняшнего дня, выбор «Сегодня / Все даты» в Общих, история по первому обращению с кэшем в памяти сеанса. F5 обновляет данные; собственные изменения обновляют или сбрасывают кэш. Локально, без push/PR/релиза.

## Управление

- «Сегодня» выбирает сегодняшнюю системную дату. Повтор не снимает фильтр и не перечитывает источник.
- Календарь показывает выбранный день. Для другой даты обе быстрые кнопки не выделены.
- «Все даты» снимает только дату, сохраняя поиск/фильтры столбцов. Активный режим выделен; кнопки образуют группу радиокнопок.
- Пустой день: «Нет заявок за ДД.ММ.ГГГГ», без автоматического перехода к истории.
- Дата остаётся датой заголовка спецификации, не импорта. Смена периода очищает выбор строк, сохраняя письмо и ручную сортировку. По UX-64 стандарт автоматически выбирает ASC для дня и DESC для истории; подробнее [table-filters.md](table-filters.md).

«Общие → При запуске показывать»: два варианта, локальный `UiPreferences.ShowTodayOnStartup` по умолчанию true, включая старые профили без поля. Выбор действует при следующем запуске, не входит в MDB или отменяемый снимок компоновки. Профиль читается до первого запроса/показа окна; заставка ждёт минимум две секунды и завершения первой загрузки.

## Чтение и кэш

`IOrderReader.ReadAsync` сохраняет полный Read. Новый `ReadDayAsync(DateOnly)` возвращает выбранный день. Интерфейс по умолчанию фильтрует снимок демо/JSON; MDB Tools экспортирует всю Orders перед фильтрацией. Ускорение дискового чтения этих источников не заявляется.

Windows: параметризованный `SELECT * FROM [Orders] WHERE [Дата] >= ? AND [Дата] < ?`, тип `DBTimeStamp`; начало дня включено, следующего — исключено. Для 31.12.9999 только нижняя граница. NULL-даты входят в историю, не в день. Исходное время/16 полей сохранены, индексы/схема/данные не меняются. Время/пометки читаются с тем же ограничением через JOIN по коду Orders; проверка схем/типов сохранена. `OrderDurationPreparingReader` передаёт день и сохраняет прежнюю подготовку разрешённых таблиц, без новых миграций.

AccessHost: протокол 1 дополнен операцией **17 ReadDay**, необязательной `OrderDate`. Значения 0–16/полный Read сохранены. Нет даты, другой период или повтор ID в ответе — ошибка. Это чтение, не разрешение повторять неподтверждённую запись.

До истории хранится только последний день, другой день читается отдельно. Первый глобальный поиск/«Все даты» загружает историю; затем запросы/даты фильтруют полный снимок в памяти. Фонового прогрева и SQL на каждую букву нет. Изменения коллег поступают через автообновление UX-69/71; ручные F5/Обновить доступны всегда, когда не выполняется запись.

F5 сохраняет запрос/фильтры, выбор по ID, фокус и видимую область и заменяет снимок выбранного периода (UX-71, docs/journal-auto-refresh.md). При обновлении того же контекста таблица доступна для навигации, сортировки и выбора, запись ждёт чтения. Исчезнувшие видимые ID исключаются без выбора соседней строки; смена периода/поиска по-прежнему очищает выбор. При дне прежняя история сбрасывается; следующий глобальный поиск читает её заново. При всех датах обновляется история. Ошибка оставляет старый снимок и причину; неполный результат недоступен для действий. Поиск, период, F5 и подключение другого источника доступны для восстановления.

Подтверждённые создание/редактирование/удаление/восстановление/статусы/БЛЦБ/цвет обновляют снимок по коду. Создание снимает поиск/фильтры, но сохраняет выбранный день, если все добавленные заявки имеют его дату: частичный снимок дня обновляется без чтения истории. Для другого/смешанного/неизвестного дня выбираются «Все даты»; при частичном снимке загружается полная история. При ранее загруженной истории объединённый снимок используется без дополнительного чтения. Это уточнение UX-64 сохраняет видимость всех добавленных записей. Неизвестный commit/конфликт не снимается сменой даты: явный F5 читает всю историю и разрешает сверку/повтор.

Пакет проверяет похожие заявки за даты спецификаций: отсутствующий день читается отдельно и переиспользуется для карточек этой даты. Ошибка проверки оставляет параметры с кратким предупреждением, не изображает отсутствие повторов. Это предупреждение, не уникальный ключ. После сверки неизвестного исхода формы сбрасывают прежний кэш повторов.

Во время чтения поиск/период доступны, действия со строками запрещены; пустой результат не показывается до завершения. Новый запрос отменяет прежний; поколение чтения отклоняет поздний ответ даже от игнорирующего отмену адаптера. Смена источника, собственная запись, закрытие отменяют чтение без сообщения об ошибке.

## Проверка и ограничения

Синтетические проверки: режимы запуска/профиль до показа, сохранение через Общие, «Сегодня»/календарь/история/NULL, кэш/F5/собственные изменения, ошибки/повтор, неизвестный commit, отмена/поздний ответ, исторические повторы пакета. Окно: две темы, 100/150%, 1280×720.

Нативный Windows-контур: границы суток 00:00:00/23:59:59/следующее 00:00:00, время/гибка/комментарий, пустой день, сохранность схемы/байтов. Обязательная x64→AccessHost x86 проверка вызывает ReadDay. На Linux нативные тесты пропускаются; реальная скорость Jet/SMB и работа старого EXE требуют Windows. Без подходящего индекса SELECT дня может сканировать таблицу; ускорение сети не гарантируется.

Локальная проверка 18.10.2026: общий `scripts/check.sh` — Release без предупреждений/ошибок, 1131 успешный тест и 16 необязательных пропусков, 20 Python-тестов; 67 нативных Access-проверок пропущены на Linux. После последних уточнений отмены, доступности письма/обновлений при ошибке и двухстороннего выбора периода прошли ещё все 145 целевых Release-проверок. Снимки двух тем просмотрены, рабочая MDB/спецификации/Figma не менялись.

Проверка UX-64: Release собирается без предупреждений и ошибок; 65 связанных сценариев прошли, включая 7 новых. Общий набор после обновления трёх прежних ожиданий проверен двумя взаимодополняющими последовательными запусками: 532 + 644 = 1176 успешных тестов, 12 + 4 = 16 необязательных пропусков. Это все 1192 сценария Jornal.Tests. Один повторный монолитный запуск получил SIGTERM без результата, поэтому итог подтверждён раздельными запусками на той же Release-сборке. Также прошли 20 Python-проверок; 67 нативных Access-проверок штатно пропущены на Linux. Обе темы, 1280×720, 100/150%, сохранение координат заголовков и высоты таблицы; снимки обоих периодов просмотрены. Рабочая MDB/Figma не менялись, без push/PR/релиза. Нативная Windows/Jet/SMB проверяется отдельно.
