# Code signing policy

## Текущий статус

Journal распространяется под MIT; сторонние компоненты сохраняют собственные лицензии и уведомления. Владелец выбрал направление SignPath Foundation для будущей подписи открытого проекта. Заявка в бесплатную программу отправлена 16.10.2026; форма показала «Form submitted — Thank you, we'll be in touch soon». По письму, переданному пользователем 16.10.2026, команда подтвердила получение заявки и ожидает ответить в течение нескольких рабочих дней с дальнейшими шагами или уточнениями. Одобрения ещё нет, сертификат не получен, автоматическое подписывание не подключено. Публичные `2026.1.0-alpha.2`–`alpha.4` остаются без Authenticode-подписи собственного кода. После обновления до alpha.4 пользователь предоставил отчёт о блокировке AccessHost политикой Smart App Control; сверка EXE с пакетом выпуска и границы проверки описаны в [диагностике Windows](windows-signing.md#обновление-до-alpha4-заблокирован-accesshost--16102026).

Не считать наличие SHA-256, успешный CI или подпись Git-коммита подтверждением Authenticode-подписи Windows. Не устанавливать доверенный корневой сертификат и не менять защиту Windows/Касперского автоматически.

## Ответственность

- Автор, сопровождающий и проверяющий изменения: [DenisPapushaJava](https://github.com/DenisPapushaJava).
- Одобрение будущих запросов на подпись и публикацию: DenisPapushaJava.
- Изменения проходят PR и обязательные проверки Linux/Windows. Ключи/учётные данные подписи не передаются заданиям внешних PR.
- До подключения SignPath нет утверждения «Free code signing provided by SignPath.io, certificate by SignPath Foundation». Такое указание появится только после фактического одобрения и получения услуги.

## План подписанного выпуска

Подписывать собственный код, launcher, Update/Setup, AccessHost и итоговый OfflineSetup с SHA-256 и меткой времени. Учитывать ограничения провайдера на сторонние бинарные файлы. Сначала согласовать поддерживаемую последовательность упаковки Velopack/Inno Setup с SignPath, затем подключать интеграцию; не переподписывать готовый пакет без пересборки feeds и контрольных сумм.

Подпись разрешена только для проверенного коммита выпуска на `main`, после ручного одобрения. До публикации проверяются подписи, соответствие исходникам, установка, MDB-хост и обновление на Windows. Приватный ключ хранит выбранный провайдер; он не входит в Git, установщик, артефакты или приложение.

Опубликованные файлы и теги не заменяются. Исправление поставляется новой версией. Для управляемых ПК решение о запуске остаётся за действующей политикой организации, даже при наличии подписи.

## Конфиденциальность

Journal не содержит рекламной аналитики и не отправляет содержимое MDB, спецификаций, результата, локальные пути или персональные настройки внешним сервисам. Эти файлы исключаются из публичных сборок.

Установленная версия автоматически обращается к GitHub Releases при запуске и раз в 6 часов до обнаружения обновления. Это передаёт обычные сведения HTTP-запроса, включая IP-адрес и заголовки клиента; скачивание пакета выполняется по команде пользователя. Политика GitHub: [GitHub Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement). В текущем коде автопроверка включена по умолчанию, её можно отключить в окне колокольчика: «Проверять обновления автоматически». Выбор сохраняется; отключение отменяет фоновый запрос/таймер, ручная проверка остаётся доступной. В опубликованной alpha.2 такого выключателя ещё нет. Финальные требования SignPath к уведомлению при установке нужно согласовать до подключения подписи.

Диагностический скрипт создаёт отчёт локально и никуда его не передаёт. Отчёт может содержать локальные пути и сообщения корпоративной политики; пользователь сам решает, какие сведения передать ИТ/разработчику.
