# Буфер обмена выбранных заявок — UX-48

20.10.2026: результат для письма поддерживает локальный «Порядок строк»
(прежняя сортировка по толщине/материалу или хронология выбора). Непустое
формирование по последнему уточнению заканчивается одним переносом (`\n` после
данных), который передаётся всеми тремя форматами; при копировании новые переносы
не добавляются, ручные правки сохраняются. Подробности — docs/settings.md,
«Порядок строк результата». «Задание на резку» сохраняет отдельные правила
группировки/сортировки ниже.

Уточнение курсора после вставки 20.10.2026: HTML сохраняет все завершающие
строки, последний пустой абзац содержит обычный NBSP, чтобы почтовый редактор
не удалял его как пустой хвост. Text/RTF остаются точными; zero-width-маркеры
не добавляются. Подробности и границы изолированной проверки — docs/settings.md.

Команды используют снимок выбранных видимых заявок. MDB не изменяется, текст результата для письма сохраняется. Автоматической отправки сообщений нет. Для каждой заявки требуется заполненный БЛЦБ; для «Задание на резку» и «Создать папки» он также должен совпадать у всего набора. Сначала проверяется весь набор, при ошибке прежний буфер не заменяется.

## Сообщения проверки выбора

Уточнение 18.10.2026 по обращению пользователя: проверяется весь выбранный набор, сообщение перечисляет заявки без БЛЦБ и их точное количество. Решение реализации для больших наборов — первые пять номеров и «ещё N», длинные/пустые номера безопасно сокращаются с кодом записи. Это проверка подготовки команды, прежний буфер и письмо сохраняются. Сообщение привязано к набору ID: смена/снятие выбора или фильтра очищает его, сортировка/смена активной строки того же набора и смена статуса сохраняют. Успешное исправление БЛЦБ повторно проверяет причину; до успеха нет скрытия по таймеру. Крестик закрывает только это сообщение, следующая команда проверяет заново. Ошибки чтения/записи/буфера не очищаются выбором или этим крестиком. Неопределённый commit и необходимость F5 сохраняются.

## Комментарии

Дополнение пользователя 18.10.2026: разные БЛЦБ считаются возможной ошибкой выбора/ввода и блокируют обе массовые команды до подготовки текста или диалога папок. Сравнивается полный номер после прежней нормализации пробелов `Line`, с учётом регистра, префикса и ведущих нулей; одинаковый числовой хвост не означает совпадение. Подсказка показывает число разных значений, первые три с примером спецификации и количеством остальных заявок в группе, затем число оставшихся БЛЦБ. Длинные значения/номера сокращаются безопасно для Unicode. Правила исчезновения и ручного закрытия те же, что у отсутствующего БЛЦБ; исправление не запускает действие автоматически.

«Комментарий строки» доступен для одной выбранной заявки. Прежний формат:

```text
(2,5 мм)  1017-1234,  Иван,  (Пример),  РП-00012345
```

«Задание на резку» (прежняя кнопка «Telegram комментарий») работает с набором с одним БЛЦБ. Сначала выделяются отдельные шапки по менеджеру и заказчику, внутри — группы станков. Четыре прежних станка идут в прежнем порядке, новые добавляются после них. По уточнению пользователя обрамление `**` убрано. В каждой группе станка строки сортируются по числовой толщине от меньшей к большей, независимо от выбора и сортировки таблицы. При равной толщине — по материалу, затем коду записи; неизвестная толщина идёт в конце. Правило действует также для новых станков. Остальные подписи, пробелы и пустые строки сохранены:

```text
12345  Иван (Пример)
2,5 мм Ст3   на Лазер

```

В шапке используются последние пять цифр без ведущих нулей. Это сокращение только для вывода: проверка совпадения выполняется раньше по полному номеру. Нечисловой номер сохраняется полностью. Нулевой номер отображается как `0`. Старая проверка длины больше пяти заменена проверкой непустого номера. Управляющие символы и переносы внутри исходных полей превращаются в пробелы только для подготовки вывода; MDB не меняется.

## Создать папки

Диалог показывает все будущие имена, число папок и число изменённых имён. Исходное имя видно в подсказке. До «Скопировать папки» файловая система не меняется. Основа имени — обычный комментарий строки; запрещённые Windows-символы заменяются, конечные точки/пробелы удаляются, имена устройств защищаются. Длинные имена сокращаются посередине; совпадения без учёта регистра получают числовой суффикс. Предел 140 символов дополнительно уменьшается под длину локального пути; максимум 1000 папок за операцию. При слишком длинном пути операция отклоняется до создания.

Папки создаются в отдельном каталоге `LocalApplicationData/Journal/Clipboard/b-<guid>`, передаются системному буферу как файлы с намерением **копировать**, затем пользователь вставляет их в нужную папку проводника. В Windows добавляется `Preferred DropEffect=1`, в Linux — `x-special/gnome-copied-files` вместе со стандартными файловыми элементами Avalonia. Каталог назначения приложение не выбирает.

Файлы пользователя не удаляются. При следующем успешном копировании очищаются только собственные наборы старше семи дней с правильными маркерами и исключительно пустыми ожидаемыми папками. Наличие постороннего файла/подкаталога, ссылки, повреждённого маркера исключает набор из очистки. Рекурсивного удаления в реализации нет. При выходе и при новой операции прежние наборы не удаляются: пользователь может вставить их после закрытия Journal. Заполненные или вручную изменённые временные папки остаются для ручного разбора.

Ошибка системного буфера показывается в интерфейсе и безопасной диагностике без содержимого комментария/имён. Во время копирования повторная операция и закрытие задействованных окон блокируются. Ошибка не повторяет запись в БД, поскольку её здесь нет.

Автотесты проверяют точный текст с актуальным форматом Telegram, числовую сортировку внутри каждого станка при обратном выборе, смешанные шапки/станки, столкновения номеров, текущий выбор, сохранение письма, недопустимые/длинные имена, коллизии и Unicode, защиту чужих файлов и ссылок при очистке, платформенный файловый payload и обе темы диалога. ## Результат для письма — 19.10.2026

Кнопка и «Копировать для письма» используют общий путь ResultClipboardContent →
ResultClipboardPayload: один элемент text + HTML + RTF, без изображения или
вложения. По последнему поручению пользователя всегда готовятся редактируемые
HTML-строки в одной div-обёртке, без таблицы и белой подложки. Выбора формата
нет. Ручной текст, Unicode, цены и сортировка не переформировываются при
копировании. Состав текста и прежний RTF сохраняются, HTML использует свободные
переносы вместо строгих колонок. Контракт и пределы проверки —
[настройки](settings.md#копирование-результата-для-письма--19102026).

В Mailspring 1.26.0 table входит в UNEDITABLE_TAGS и превращается в неделимый
HTML-блок; это не растровая картинка. Причина проверена по официальным исходникам:
[uneditable-plugins.tsx](https://github.com/Foundry376/Mailspring/blob/1.26.0/app/src/components/composer-editor/uneditable-plugins.tsx),
[base-mark-plugins.tsx](https://github.com/Foundry376/Mailspring/blob/1.26.0/app/src/components/composer-editor/base-mark-plugins.tsx).
Единый внешний HTML-элемент — требование
[CF_HTML](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format).
Получатель сам выбирает и интерпретирует формат. Нельзя обещать одинаковый вид
во всех клиентах; полевая проверка вставки/правки/полученного письма остаётся
отдельной от структурных тестов.
