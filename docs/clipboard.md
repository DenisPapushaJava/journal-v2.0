# Буфер обмена выбранных заявок — UX-48

Команды используют снимок выбранных видимых заявок. MDB не изменяется, текст результата для письма сохраняется. Автоматической отправки сообщений нет. Для каждой заявки требуется заполненный БЛЦБ; сначала проверяется весь набор, при ошибке прежний буфер не заменяется.

## Комментарии

«Комментарий строки» доступен для одной выбранной заявки. Прежний формат:

```text
(2,5 мм)  1017-1234,  Иван,  (Пример),  РП-00012345
```

«Задание на резку» (прежняя кнопка «Telegram комментарий») работает с набором. Сначала выделяются отдельные шапки по полным БЛЦБ, менеджеру и заказчику, внутри — группы станков. Четыре прежних станка идут в прежнем порядке, новые добавляются после них. По уточнению пользователя обрамление `**` убрано. В каждой группе станка строки сортируются по числовой толщине от меньшей к большей, независимо от выбора и сортировки таблицы. При равной толщине — по материалу, затем коду записи; неизвестная толщина идёт в конце. Правило действует также для новых станков. Остальные подписи, пробелы и пустые строки сохранены:

```text
12345  Иван (Пример)
2,5 мм Ст3   на Лазер

```

В шапке используются последние пять цифр без ведущих нулей. Нечисловой номер сохраняется полностью; при столкновении сокращённых номеров для того же менеджера/заказчика показываются оба полных номера. Нулевой номер отображается как `0`. Старая проверка длины больше пяти заменена проверкой непустого номера. Управляющие символы и переносы внутри исходных полей превращаются в пробелы только для вывода.

## Создать папки

Диалог показывает все будущие имена, число папок и число изменённых имён. Исходное имя видно в подсказке. До «Скопировать папки» файловая система не меняется. Основа имени — обычный комментарий строки; запрещённые Windows-символы заменяются, конечные точки/пробелы удаляются, имена устройств защищаются. Длинные имена сокращаются посередине; совпадения без учёта регистра получают числовой суффикс. Предел 140 символов дополнительно уменьшается под длину локального пути; максимум 1000 папок за операцию. При слишком длинном пути операция отклоняется до создания.

Папки создаются в отдельном каталоге `LocalApplicationData/Journal/Clipboard/b-<guid>`, передаются системному буферу как файлы с намерением **копировать**, затем пользователь вставляет их в нужную папку проводника. В Windows добавляется `Preferred DropEffect=1`, в Linux — `x-special/gnome-copied-files` вместе со стандартными файловыми элементами Avalonia. Каталог назначения приложение не выбирает.

Файлы пользователя не удаляются. При следующем успешном копировании очищаются только собственные наборы старше семи дней с правильными маркерами и исключительно пустыми ожидаемыми папками. Наличие постороннего файла/подкаталога, ссылки, повреждённого маркера исключает набор из очистки. Рекурсивного удаления в реализации нет. При выходе и при новой операции прежние наборы не удаляются: пользователь может вставить их после закрытия Journal. Заполненные или вручную изменённые временные папки остаются для ручного разбора.

Ошибка системного буфера показывается в интерфейсе и безопасной диагностике без содержимого комментария/имён. Во время копирования повторная операция и закрытие задействованных окон блокируются. Ошибка не повторяет запись в БД, поскольку её здесь нет.

## Проверки и границы

Автотесты проверяют точный текст с актуальным форматом Telegram, числовую сортировку внутри каждого станка при обратном выборе, смешанные шапки/станки, столкновения номеров, текущий выбор, сохранение письма, недопустимые/длинные имена, коллизии и Unicode, защиту чужих файлов и ссылок при очистке, платформенный файловый payload и обе темы диалога. Linux Headless не доказывает настоящую вставку в Windows Explorer/Nemo; нативная вставка, в том числе в сетевую папку, требует ручного прогона. Функции не меняют MDB или локальную тестовую копию.
