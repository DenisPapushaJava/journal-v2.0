# Цвет строк и подсказки ввода — UX-49

## Цвет выбранных заявок

«Цвет…» открывает палитру и предпросмотр для выбранных строк. Есть 29 готовых цветов и произвольный ввод `#RRGGBB` либо прежнего знакового ARGB. Применяется только непрозрачный цвет; например, `#FF9DFF` — прежний `-25089`. Значение `-1` по прежнему контракту означает снятие отметки. Цвета статусов разрешены: они дают соответствующую стандартную подпись, остальные цвета отдельной подписи не получают.

Нажатие «Применить» вызывает прежнюю транзакционную массовую операцию с исходными снимками выбранных записей. Меняется только `Color`, схема и остальные поля остаются прежними. Конфликт или неизвестный исход сохраняют введённый цвет и требуют F5; повторного автоматического запроса нет. Кнопка недоступна без выбранных строк или в источнике без записи.

«Код цвета» открывает такую же палитру, но подтверждение копирует только знаковое десятичное число ARGB. Заявки и текст письма не изменяются. Выбор строк не обязателен. Если у выбранных заявок один общий цвет, он подставляется в палитру; иначе начальный цвет берётся из локальной настройки новых заявок. Во время копирования повтор и закрытие задействованных окон блокируются.

Настройка цвета новых заявок остаётся отдельной: перекрашивание выбранного набора её не меняет. Код цвета не устанавливает авторство.

## Менеджеры и заказчики

«Настройки → Общие → Менеджеры и заказчики» открывает два списка, одно значение на строку, с «Сохранить» и «Отмена». Пустые строки убираются, края обрезаются, дубли без учёта регистра объединяются с сохранением первого написания и порядка. Запятая — часть имени, а не разделитель.

Списки содержат до 200 значений каждый, значение — до 255 символов без управляющих знаков, общий объём — до 16000 символов. Ограничение укладывает даже экранированный Unicode в прежний предел файла настроек 128 KiB. Ошибка проверки или записи оставляет диалог и ввод открытыми; при отказе записи прежние рабочие списки восстанавливаются.

Подсказки появляются после первого символа по вхождению текста без автодописывания. Пользователь может выбрать подсказку или ввести любое другое допустимое имя. Пустой список оставляет обычное текстовое поле. Подсказки подключены к новой, пакетной и редактируемой заявкам; существующие имена и незавершённый ввод ими не заменяются. Очистка поля нормализует пустое значение, включая null от AutoCompleteBox.

Сохранение — необязательное `EntrySuggestions` в локальном `ui-settings.json` версии 1. Старые профили без списков читаются как пустые; неподходящие значения списков сбрасываются с сообщением, тема и компоновка сохраняются. Сброс компоновки не сбрасывает списки. MDB и Linux-копия не содержат этих справочников. Автоматического заполнения из истории и переноса старого конфига здесь нет.

## Проверки

Автотесты проверяют HEX/ARGB, выбор и неизменность остальных полей, конфликт, копирование без записи и сохранность письма, закрытие во время операции, нормализацию/ограничения списков, профиль близко к лимиту, старый/повреждённый профиль, отказ записи и повторное открытие, свободный ввод/очистку/раскрытие автоподсказок. Диалоги проверяются в обеих темах на минимальных размерах; перезапуск обновления недоступен при вложенном редакторе списков. Нативная проверка цвета дополнена `-25089` с повторным чтением и сверкой схемы; она исполняется только в Windows Jet/ACE. Работа старого EXE и общая SMB-папка остаются отдельным ручным прогоном.

Локальный итог этапа: 857 тестов успешны, 16 частных/платформенных пропущены; 20 release/CI-проверок успешны. 55 нативных Access-тестов на Linux пропущены. Debug/Release собраны без предупреждений и ошибок. Дополнительная проверка автоподсказок с клавиатуры прошла отдельно в обеих темах. Рабочая MDB и пользовательская тестовая копия не менялись.
