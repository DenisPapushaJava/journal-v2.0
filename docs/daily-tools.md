# Цвет строк и подсказки ввода — UX-49

## Цвет выбранных заявок

«Цвет…» открывает палитру и предпросмотр для выбранных строк. Есть 29 готовых цветов, точный выбор «Больше цветов» и произвольный ввод `#RRGGBB` либо прежнего знакового ARGB. Применяется только непрозрачный цвет; например, `#FF9DFF` — прежний `-25089`. Значение `-1` по прежнему контракту означает снятие отметки. Цвета статусов разрешены: они дают соответствующую стандартную подпись, остальные цвета отдельной подписи не получают. После выбора готового цвета/на круге поле показывает HEX, а предпросмотр — пример читаемой строки.

Нажатие «Применить» вызывает прежнюю транзакционную массовую операцию с исходными снимками выбранных записей. Меняется только `Color`, схема и остальные поля остаются прежними. Конфликт или неизвестный исход сохраняют введённый цвет и требуют F5; повторного автоматического запроса нет. Кнопка недоступна без выбранных строк или в источнике без записи.

Если у выбранных заявок один общий цвет, он подставляется в палитру; иначе начальный цвет берётся из локальной настройки новых заявок. Во время применения повтор и закрытие задействованных окон блокируются. По явному уточнению пользователя 18.10.2026 отдельная кнопка «Код цвета» и режим копирования ARGB удалены: в первой программе они служили ручному переносу кода в конфиг, теперь свой цвет новых заявок задаётся в Общих. Ручной ввод цвета в палитре и совместимый знаковый формат Color в MDB сохраняются.

Настройка цвета новых заявок остаётся отдельной: перекрашивание выбранного набора её не меняет. Цвет не устанавливает авторство.

## Точная палитра — UX-53, 18.10.2026

По предоставленному пользователем образцу выбран круг с радужным кольцом оттенка и внутренним треугольником насыщенности/яркости. «Больше цветов» открывает компактную Flyout-панель: она позиционируется средствами Avalonia с учётом доступной области и не увеличивает прокручиваемое тело диалога. Это заменяет первоначальное раскрытие внутри окна, при котором часть палитры оказывалась за его границей. В панели есть текущий образец и HEX, в диалоге остаются предпросмотр и «Применить». Клик снаружи закрывает панель, первый Esc закрывает её, следующий — сам диалог. Закрытие панели не применяет и не теряет выбранный цвет.

`ColorWheel` — переиспользуемый контрол без дополнительных пакетов: кэшируемый растр кольца и треугольника, указатели с тёмной/светлой обводкой. Перемещение по кольцу меняет оттенок; по треугольнику — насыщенность/яркость. Захват указателя обеспечивает перетаскивание, выход за треугольник ограничивает выбор ближайшей границей; отпускание/потеря захвата прекращает выбор. С клавиатуры ←/→ меняют оттенок, ↑/↓ — яркость, Shift+←/→ — насыщенность. Инструкция только в подсказке/доступном описании, без постоянного поясняющего текста.

VM хранит HSV без обратного округления при каждом движении; код, готовые цвета, предпросмотр и указатели синхронизируются в обе стороны. Серый/белый/чёрный сохраняют выбранный оттенок для дальнейшего уточнения. Прозрачность фиксирована; запись, конфликты и неопределённый commit используют прежний путь Color. Рабочая MDB/локальная пользовательская копия не менялись; новая палитра пока локальная, без push/PR/релиза.

20.10.2026: тот же ColorWheel доступен для личного цвета новых заявок:
«Настройки → Общие → Заявки → Использовать свой цвет → Больше цветов».
Отдельный Flyout не меняет размер страницы; закрывается по Esc/клику снаружи
и вместе с настройками. Выбор сохраняется через прежний NewOrderColor, а не
пишется в существующие строки. Зарезервированные −1/цвета статусов отвергаются
с сохранением последнего допустимого кандидата. Контракт — [настройки](settings.md).

## Данные для выпадающих списков

«Настройки → Общие → Данные для выпадающих списков» открывает три списка: менеджеры, заказчики, материалы. Одно значение на строку, общее «Сохранить» и «Отмена». Пустые строки убираются, края обрезаются, дубли без учёта регистра объединяются с сохранением первого написания и порядка. Запятая — часть значения, а не разделитель. Окно 960×560, минимум 760×440; три равные колонки и общие узкие полосы прокрутки.

Списки содержат до 200 значений каждый, значение — до 255 символов без управляющих знаков, общий объём — до 16000 символов. Ограничение укладывает даже экранированный Unicode в прежний предел файла настроек 128 KiB. Ошибка проверки или записи оставляет диалог и ввод открытыми; при отказе записи прежние рабочие списки восстанавливаются.

По уточнению пользователя 18.10.2026 менеджер и заказчик ищутся после первого символа строго с начала названия, без учёта регистра и без автодописывания. «Р» показывает «Роман»/«Руслан», но не «Пётр»/«Артём». Пользователь может выбрать подсказку или ввести другое допустимое имя.

Материал — редактируемый выпадающий список: стрелка показывает все сохранённые марки независимо от текста, выбор переносит значение, ввод своей марки остаётся свободным. Используется штатный editable ComboBox Avalonia без копирования его шаблона. Работают мышь/стрелки клавиатуры и закрытие Esc без закрытия заявки; текст не дополняется автоматически, раскрытие не меняет значение/подтверждение импорта. Пустой список оставляет обычное текстовое поле. Подсказки подключены к новой, пакетной и редактируемой заявкам; существующие имена и незавершённый ввод ими не заменяются. Очистка поля нормализует пустое значение, включая null от элементов ввода.

Рамку и фон редактируемого списка рисует внешний ComboBox; вложенный PART_EditableTextBox остаётся прозрачным и не получает обычную заливку TextBox при фокусе/наведении. Это сохраняет целый левый край рамки, включая фокус и проверку AWJC, в обеих темах. Фокус/ввод и узкая прокрутка списка сохраняются.

Уточнение 18.10.2026: список «Материалы» содержит произвольные марки, включая алюминий; это локальные подсказки, а не обязательный закрытый справочник. Они наследуются первой и последующими карточками пакета, не подменяют распознанную/историческую марку и не меняют правила допустимости материала для разных профилей. Для AWJC сохранены янтарная рамка и кнопка подтверждения внутри редактируемого списка, перед стрелкой; ручная правка/выбор другого значения снимают проверку как прежде. Время, коэффициент и расчёт цены не меняются.

Сохранение — необязательное `EntrySuggestions` в локальном `ui-settings.json` версии 1. По уточнению пользователя 18.10.2026 (UX-66) в приложение включён стартовый набор с этого компьютера: 2 менеджера, 2 заказчика и 4 материала, с сохранением написания и порядка. Набор хранится отдельно в `src/Jornal.Desktop/Customization/Data/entry-suggestions.json` и встроен в DLL; разработчик меняет его обычным выпуском, без чтения чужого профиля при сборке. В редакторе каждое значение уже находится на своей строке.

Первый запуск без профиля и прежний профиль без `EntrySuggestions` (или с `null`) получают стартовый набор. Существующий объект списков имеет безусловный приоритет: выпуск не заменяет и не объединяет его со стартовым набором, даже если сохранены пустые массивы или пустой объект. Прежние два списка без `Materials` сохраняются с пустыми материалами. Само чтение списков не перезаписывает настройки; однократный переход панелей UX-68 может сохранить профиль, полностью сохранив эти списки. После завершения перехода повторные чтения файл не меняют; обычное сохранение фиксирует рабочий набор как личные списки. Подсказки не заполняют сами поля заявки и не ограничивают свободный ввод.

Неподходящие значения списков сбрасываются с сообщением, тема и компоновка сохраняются. Общий лимит 16000 символов относится ко всем трём спискам вместе. Сброс компоновки не сбрасывает списки. MDB и Linux-копия не содержат этих справочников. Автоматического заполнения из истории и переноса старого конфига здесь нет. Все будущие изменения стартового набора обязаны сохранять приоритет пользовательских списков, в том числе намеренно очищенных.

## Проверки

Автотесты проверяют HEX/ARGB, выбор и неизменность остальных полей, конфликт и сохранность письма, закрытие во время применения, нормализацию/ограничения списков, профиль близко к лимиту, старый/повреждённый профиль, отказ записи и повторное открытие, свободный ввод/очистку/раскрытие автоподсказок. Для UX-53 проверяются точность HSV, память оттенка, мышь/захват/выход за границы, клавиатура, ручной код после выбора на круге, отсутствие записи до подтверждения, границы Flyout и доступность предпросмотра/подтверждения в минимальном окне у края экрана, отсутствие прежней кнопки «Код цвета». Диалоги проверяются в обеих темах; перезапуск обновления недоступен при вложенном редакторе списков. Нативная проверка цвета дополнена `-25089` с повторным чтением и сверкой схемы; она исполняется только в Windows Jet/ACE. Работа старого EXE и общая SMB-папка остаются отдельным ручным прогоном.

Локальный итог первоначального этапа UX-49: 857 тестов успешны, 16 частных/платформенных пропущены; 20 release/CI-проверок успешны. 55 нативных Access-тестов на Linux пропущены. Debug/Release собраны без предупреждений и ошибок. Дополнительная проверка автоподсказок с клавиатуры прошла отдельно в обеих темах. Это исторический итог до UX-53. Рабочая MDB и пользовательская тестовая копия не менялись.
