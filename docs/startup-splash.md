# Заставка Journal

Поручена пользователем 16.10.2026. Логотип компании **БЛОК** и текущая версия приложения обязательны на всех вариантах, в том числе праздничных. Отдельная строка «Блок-Производство» убрана по уточнению пользователя; логотип сохраняется. Обычные сюжеты: лазерная, плазменная, гидроабразивная резка и гибка. Иногда выпускаем тематическое праздничное оформление. Решение записано в навыке дизайна, UX-21.

## Устройство

`src/Jornal.Desktop/Startup/` содержит небольшое окно `SplashWindow`, выбор фона `StartupArtwork.Current` и переход к рабочему окну `DesktopStartup`. Точка сборки зависимостей остаётся в `App.CreateMainWindow`: оформление не зависит от Access, парсера или обновлений.

`App` назначает заставку начальным `MainWindow`. После её открытия отложенная задача UI строит пока скрытое рабочее окно и вызывает `LoadInitialOrdersAsync`. По уточнению пользователя заставка видна **минимум 2 секунды и до завершения первой загрузки всего списка**: быстрая база не сокращает две секунды, медленная удерживает заставку дольше. Время отсчитывается от открытия окна монотонным `Stopwatch`; ожидание асинхронное. Статус меняется на «Загружаем заявки…», без вымышленных процентов. При отказе MDB/AccessHost загрузчик сохраняет прежнюю типизированную ошибку: по завершении минимального времени показывается рабочее окно с причиной и обычной помощью. При ошибке самого создания окна сообщение остаётся на заставке. После назначения рабочего `MainWindow` заставка закрывается. Тихая проверка обновлений начинается только после открытия рабочего окна и не задерживает заставку.

Первая загрузка кэшируется как задача окна: `OnOpened` ожидает её, не выполняя повторное чтение MDB. Обычный F5 сохраняет прежнее поведение. Черновик результата после обновления извлекается из профиля только при открытии рабочего окна: отмена на заставке не забирает сохранённый текст. Закрытие заставки отменяет ожидание двух секунд и текущую команду чтения; скрытое окно не появляется. Если отказ произошёл ещё до построения рабочего окна, показывается ошибка запуска с закрытием. Декоративная картинка при ошибке загрузки пропускается; при недоступности самого логотипа остаётся текстовое название компании. Подробность ошибки записывается через `Trace`.

Заставка 640×360 логических px, без рамки ОС, с кнопкой закрытия, Escape и обычным Alt+F4. Не закрепляется поверх других приложений. Оформление одинаковое в обеих темах; сохранённая тема рабочего окна по-прежнему восстанавливается из профиля. Изображения освобождаются при закрытии.

## Как поменять оформление к выпуску

1. Подготовить фон 16:9, рекомендуемый размер **1280×720**, JPEG до **160 КиБ**. Это инженерный бюджет текущей реализации, а не пользовательский лимит для всего приложения. Левая часть должна оставаться тёмной и спокойной под логотип и название, нижняя — читаемой под статус и версию. Не встраивать в фон логотип, версию, прогресс или текст интерфейса.
2. Положить выбранный фон в `docs/design/assets/startup/` и указать его URI в `StartupArtwork.Current`. Поставлять только выбранный фон; предыдущие варианты сохраняет Git, без накопления сезонных картинок в дистрибутиве. Для файла с другим расширением также изменить `AvaloniaResource` в Desktop csproj.
3. Обновить `docs/design/assets/startup/artwork-source.json`: происхождение, описание/промпт, размер и хеш выбранного файла. Пользовательский `logo.png` переиспользуется отдельным встроенным ресурсом, без перерисовки и смены пропорций. Версия автоматически читается из `AssemblyInformationalVersion`, суффикс alpha/beta/dev сохраняется, хеш коммита не выводится.
4. Выполнить `JOURNAL_SCREENSHOT_DIR="$PWD/.local/startup-preview" ./scripts/dotnet.sh test tests/Jornal.Tests/Jornal.Tests.csproj -c Release --filter FullyQualifiedName~StartupTests`, посмотреть снимки, затем обычные проверки этапа. Проверяются логотип/версия, размер фона, минимум 2 секунды, ожидание полного списка без повторного чтения, закрытие/отмена загрузки, ошибка и недоступная база. DPI/реальное переключение окон проверить на Windows перед раздачей.
5. Доставить оформление обычным выпуском Journal. В интерфейсе, `ui-settings.json` и пользовательских каталогах нет выбора/переопределения фона; приложение не читает произвольный путь к картинке из профиля. Это управление составом выпуска, не защита от самостоятельной модификации бинарных файлов.

Базовый фон сгенерирован встроенным `image_gen` по мотивам предоставленных фотографий лазерной резки; исходные фотографии не подменялись. Для поставки изображение уменьшено и перекодировано в JPEG, **88 926 байт** (около 87 КиБ). Логотип — исходный `logo.png`, **1 583 байта**. Новых зависимостей не добавлено; исходник генерации большого размера хранится локально, в поставку не входит. Полный промпт и параметры — в `artwork-source.json`.

Переход окон учитывает [модель времени жизни Avalonia](https://docs.avaloniaui.net/docs/fundamentals/application-lifetimes). Проверки headless не заменяют реальный прогон Windows с масштабированием.
