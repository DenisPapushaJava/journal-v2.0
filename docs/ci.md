# Состав проверок CI

Реализация этапа 17.10.2026: `.github/workflows/modern.yml` определяет состав по полному diff через `scripts/ci_scope.py`. Workflow запускается на каждом PR и push в main, без исключения файлов на уровне события. Имена обязательных проверок `Check (ubuntu-latest)` / `Check (windows-latest)` и защита main сохранены.

| Изменения | Что запускается |
| --- | --- |
| Markdown в docs/навыках, README/AGENTS/LICENSE/PR-шаблон; четыре известных файла VS Code | Быстрые Python-проверки инструментов/классификации и JSON/JSONC настроек; без .NET и упаковки |
| Обычные C#/AXAML приложения, парсер, результат, локальное/демохранилище, обычные тесты | Всё выше + Release-сборка/тесты Linux и Windows, обязательные транзакционные тесты Jet x86 |
| AccessHost/Windows Access-адаптер/DTO Orders и прайсов, обновления/запуск/источник, ресурсы поставки, зависимости/проекты, workflow/скрипты, интеграционные фикстуры/тесты | Полный цикл, включая пакеты обеих ОС, Windows OfflineSetup, x64-клиент → установленный x86-хост, установку/обновление/перезапуск и Jet |
| Неизвестный путь, пустой diff, недоступный диапазон Git; ручной CI | Полный цикл |
| Тег выпуска или ручной Release с версией | Прежний безусловный полный Release; черновик создаётся только для тега после успешных пакетов обеих платформ |

Известные пути задаются в одном классификаторе. Новые компоненты сначала считаются требующими полного прогона; перенос в обычную группу — отдельное осознанное изменение с тестом. Изображения/иконки/встроенные ресурсы под docs не считаются чистой документацией. Смешанные изменения получают наиболее полный необходимый набор.

PR сравнивается с merge-base головы и базы; push — целиком от before до after, включая несколько коммитов. Переименование учитывает старый и новый путь; удаления тоже учитываются. SHA проверяются до передачи Git, команды не выполняются через shell. Результат записывается в summary запуска.

## Защита от ложного успеха

Job состава обязан завершиться успешно и передать оба булевых значения. Оба обязательных Check запускаются через always(), затем явно проверяют результат состава и согласованность флагов. Ошибка, отмена, пропуск или отсутствующий результат не превращаются в зелёный пропуск сборки. Зависимые шаги сохраняют обычное прекращение после ошибки. Jet не привязан к флагу упаковки: он обязателен для любого кода. Имена required checks и настройки защиты не меняются.

При добавлении файлов/типов проверок обновляйте классификатор и его таблицу случаев. Для изменения доступа к MDB по-прежнему требуется нативный Windows-контур; тесты Linux и разбор путей его не заменяют.

Локально:

```bash
python3 -m unittest discover -s tests/release -v
python3 scripts/ci_scope.py check
```

Проверки включают реальные временные Git-репозитории: несколько push-коммитов, переименование из кода в docs, отставшую PR-ветку, недоступный диапазон, пробелы, классы файлов и отказ обязательного шлюза. Синтаксис обоих workflow дополнительно проверен actionlint 1.7.12. Полевые условные запуски сверять в GitHub Actions; одни локальные тесты не подтверждают прохождение удалённого CI.
