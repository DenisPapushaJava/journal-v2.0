# Длительность резки

Принято 17.10.2026: сохранять время из поддержанных HTML БЛОК/Wintech и PDF HansLaser, разрешить ручное изменение в создании/редактировании и добавить в результат после стоимости. Интерфейс и письмо используют **ЧЧ:ММ**, часы не сбрасываются после суток. Секунды из спецификации **округляются вверх до полной минуты**: `00:00:22 → 00:01`, `01:32:24 → 01:33`, `342:50:16 → 342:51`. Точное `29:46` остаётся прежним. Пустое поле означает неизвестное время, `00:00` — явно заданное нулевое.

Парсер по-прежнему отдельно извлекает исходную длительность и её источник; преобразование в минуты выполняет слой импорта. HTML берёт итоговое «Время», PDF — «Время обработки, всего». Это длительность из отчёта, а не измерение реального времени работы станка. Не суммируются времена отдельных деталей и повторённых страниц.

## Совместимость MDB

Все прежние **16 полей Orders, их порядок/типы, прайсы и строка коэффициента остаются прежними**. Согласованное исключение из первоначального запрета изменения схемы — одна отдельная таблица `JournalOrderExtras`:

| Поле | Jet-тип | Смысл |
| --- | --- | --- |
| OrderId | LONG, первичный ключ | Существующий `Orders.Код` |
| DurationMinutes | DECIMAL(18,0) | Целое число минут; Jet LONG не покрывает весь диапазон TimeSpan |
| ParametersHash | TEXT(64) | SHA-256 версии значимых параметров |
| FormatVersion | SHORT | Версия записи, сейчас 1 |

Внешних ключей, каскадов, дополнительных ограничений на Orders нет: старый EXE должен продолжать создавать, редактировать и удалять свои строки. Коэффициент не расширяется шестым сегментом: старый `Edit` принимает ровно 3 или 5 частей и иначе теряет исходный коэффициент/ID/газ.

Рабочее подключение Windows после успешного чтения один раз подготавливает таблицу. Уже существующая таблица проверяется и используется; чужая/неизвестная структура не перезаписывается. Для создания нужен исключительный доступ к MDB. До DDL рядом сохраняется полная копия `OrderDB.mdb.before-journal-extras-<UTC>-<id>.bak`; если копия не создана, DDL не начинается. Для первой подготовки следует закрыть старую/новую программу на остальных ПК. При занятости/недостатке прав обычное чтение исходной базы сохраняется, показывается пояснение, F5 повторяет подготовку. Время нельзя незаметно потерять: запись с введённым временем при отказе подготовки отклоняется с сохранением формы.

Обычные адаптеры чтения, диагностические команды и Linux не инициируют DDL. После подготовки запись Orders и дополнения выполняется в одной короткой shared-транзакции. INSERT/UPDATE/DELETE/восстановление подтверждаются до commit. Редактирование проверяет прежние поля и исходную метаинформацию времени; изменение только времени другим клиентом также является конфликтом. Корзина сохраняет время в том же локальном типизированном снимке. Удаление и восстановление дополнения выполняются вместе с Orders; исходный ID/цена сохраняются.

Копирование и DDL выполняются двумя этапами: сначала файл читается с `FileShare.None` и копия полностью записывается на диск, затем файл закрывается и Jet открывает MDB в `Share Exclusive`. Jet не разрешает копирование через второй файловый дескриптор при своём исключительном подключении. Если между этапами появился активный клиент, захват Jet завершается отказом и DDL не начинается; уже сделанная копия сохраняется. Копия отражает состояние на момент копирования, не является непрерывным журналом последующих изменений и не восстанавливается автоматически.

## Изменения старой программой

Старая программа новую таблицу не читает. У созданной ею заявки время отсутствует. Хеш включает дату/номер, станок, материал, толщину, размер/количество листов, длину, вес и исходную строку коэффициента. Изменение этих параметров без подтверждения времени делает его неактуальным. Менеджер, заказчик, цена, цвет и БЛЦБ не инвалидируют длительность. Неактуальное время остаётся в снимке, но не выводится в письмо и не предлагается как достоверное в поле; форма объясняет необходимость проверки. Чтобы подтвердить его для новых параметров, время вводят заново.

DELETE старого EXE может оставить запись дополнения без Orders; она не появляется как отдельная заявка. При конфликте занятого идентификатора дополнение не перезаписывается автоматически. Хеш снижает риск привязки времени к другой записи, но не доказывает идентичность после ручного восстановления/замены MDB или полного повторения всех параметров. Нужна проверка после таких операций; автоматической очистки чужих/осиротевших данных нет.

На Linux исходная MDB остаётся read-only: `mdb-export` читает таблицу дополнений, `mdb-tables` определяет её наличие. Требуется полный пакет mdbtools; путь команды списка можно задать через `JOURNAL_MDB_TABLES`. Локальная `.journal-test.json` сохраняет время и поддерживает создание, правки и корзину без обратной записи в MDB. Старые файлы без времени читаются как прежде.

## Столбец журнала

По уточнению пользователя время отображается также в главной таблице после стоимости. Формат ЧЧ:ММ, сортировка по общим минутам (100:00 больше 29:46). Неизвестное/неактуальное значение — «—», подсказка объясняет причину. Видимость, ширина и порядок сохраняются в прежнем профиле; новый ключ cutting-time не сбрасывает остальные столбцы старых профилей.

## Результат и проверка

В существующей ячейке стоимости добавляется `     Время резки: 29:46`, перед прежним полем «резка Лазер». У заявки без достоверного времени строка остаётся прежней. Порядок, остальные поля, форматирование суммы, HTML/RTF/Unicode и настройки шрифта сохраняются. Длительность не участвует в расчёте цены.

Автоматические сценарии: преобразование времени, ввод и пустое значение, импорт, обе темы/компактная форма, повторное чтение локального файла, корзина, форматы буфера; обязательные Windows Jet x86 — создание таблицы/копии, неизменность Orders/прайсов, запись/конфликты, старые SQL-операции, удаление/восстановление и отказ при неизвестной таблице. Реальный старый EXE, первая миграция рабочей сетевой копии и два компьютера требуют ручной проверки. Наличие тестов не является отчётом об их прохождении.
