# Локальная тестовая копия на Linux

По уточнению пользователя 16.10.2026 для разработки на Linux разрешён отдельный формат с настоящими данными. **На Windows рабочим источником остаётся исходная MDB с прежней схемой и Windows-адаптером.** Локальный формат не заменяет её и не проверяет совместимость Jet/SMB.

## Создание и подключение

В «Настройки → База данных» на Linux есть «Локальная тестовая копия» и «Создать из MDB…». Выберите отдельную закрытую копию MDB и новое имя с расширением `.journal-test.json`, дождитесь импорта, затем нажмите «Подключить». Для существующего файла доступны «Обзор…» и ввод полного пути. Шапка явно обозначает локальный тестовый источник. На Windows режим скрыт; сохранённый Linux-профиль там отклоняется, без молчаливой подмены источника.

Команда из корня проекта:

```bash
./scripts/dotnet.sh run --project tools/Jornal.Inspect -- \
  local-copy "/путь/к/копии/OrderDB.mdb" "$PWD/.local/OrderDB.journal-test.json"
```

Для импорта нужен `mdb-export` в PATH или `JOURNAL_MDB_EXPORT`. Для подготовленного локального инструмента: `export JOURNAL_MDB_EXPORT="$PWD/.local/tools/mdb-export"`. При импорте из IDE окружение должно быть у процесса VS Code. После создания копии MDB Tools для работы с ней не нужен.

Путь сохраняется в пользовательском `Journal/data-source.json`; следующий F5 в VS Code открывает выбранную копию. Настройки экрана остаются отдельно. Повторное создание поверх существующей копии запрещено, в том числе после системного диалога замены: выберите новое имя.

## Данные и операции

Импорт сохраняет всю `OrderSummary` прежнего адаптера: исходное время, строку коэффициента, неизвестные значения, NULL и историческую стоимость. Текстовые NULL, которые прежний адаптер уже представляет пустой строкой, отдельно не восстанавливаются. Переносятся первые строки всех шести прайсов, исходные подписи колонок, NULL и настоящий ноль тарифа. Имя исходной MDB, SHA-256 и время импорта сохраняются как сведения о происхождении снимка.

Работают список, поиск, фильтры, результат для письма, создание заявки, статусы, снятие цветовой отметки и БЛЦБ. Изменения сохраняются между запусками. Новая заявка получает свободный ID и цену через общий `CuttingPriceCalculator`, с прежними Double/ToEven и без минимума 500 ₽ в сохранённой стоимости. Кнопка «Рассчитать» даёт предварительную цену; изменение полей её сбрасывает. Сохранение повторно вычисляет цену. Отсутствующий/NULL тариф не создаёт неполную заявку. Старые стоимости при импорте, просмотре и изменении статуса/БЛЦБ не пересчитываются.

Используется типизированный JSON .NET без новой СУБД, Runtime и зависимостей поставки. Во время записи перечитывается текущий файл, проверяется исходное значение изменяемого поля, новый снимок сбрасывается на диск во временный файл и заменяет прежний одним переносом. Пакет неделим; конфликт требует F5. Общий `.lock` защищает от потерянных изменений между экземплярами приложения на этой машине; работающие экземпляры не должны удалять его. Это локальный тестовый режим, не замена сетевых блокировок Access. Ограничение файла — 128 МиБ.

Работают также редактирование с текущим расчётом, удаление выбранных в локальную корзину, просмотр/восстановление и окончательное удаление архивной копии. Частичный результат группы и неподтверждённые операции обозначаются отдельно. [Контракт корзины](order-maintenance.md) одинаков по сценарию, но Linux проверяет запись JSON, а не Jet/SMB.

Формат копии дополнен необязательным `Records`: полные типизированные записи для затронутых редактированием/восстановлением строк. Старые копии без поля читаются. До первого такого изменения исходная запись строится из уже нормализованной `OrderSummary`: текстовый NULL и точные биты прежнего Double восстановить из старого снимка нельзя. После сохранения полный снимок сохраняется отдельно и сверяется с таблицей. Старые сборки Linux с запретом неизвестных JSON-полей могут не открыть расширенную копию; для них используйте сохранённую прежнюю копию. Это тестовый формат, совместимость рабочей MDB со старым EXE от него не зависит.

Бизнес-парсер, комментарии и остальные ещё не перенесённые функции остаются следующими этапами. Обратной синхронизации и экспорта изменений в MDB нет. Для подтверждения Windows-записи и совместной работы старого/нового клиента нужны отдельные Windows-проверки.

## Приватность и проверка

MDB открывается только для чтения, таблицы выгружаются из одного временного снимка; его хеш сверяется с прочитанным исходным файлом. Это не транзакционная резервная копия работающей общей MDB: используйте закрытую копию. Ошибка таблицы или отмена до публикации не оставляет частичный локальный файл.

На Linux временный каталог импорта доступен только владельцу, новые локальные файлы создаются с правами 0600. MDB, `.journal-test.json`, `.lock`, реальные тарифы и снимки рабочего журнала не входят в Git. Публичные тесты используют вымышленные записи: повторное открытие, исторические поля, NULL/ноль, расчёт, отказ без тарифа, неделимость пакета, конфликты, два адаптера, отмена, повреждённый файл, запрет замены, UI обеих тем и запрет источника на Windows.

## Каталог новых станков

Локальная реализация UX-47 сохраняет необязательный Machines в JSON v1 и добавляет прайсы зарегистрированных станков к прежним шести Prices. Старые копии без Machines читаются как пустой дополнительный каталог; импорт из MDB переносит необязательный JournalMachines и соответствующие широкие прайсы. Добавление станка/редактирование/расчёт атомарно сохраняются в отдельном тестовом файле. Существующую пользовательскую копию при разработке не меняли. Это не обратная запись MDB и не проверка Windows Jet. Контракт — [прайсы](pricing.md#создание-станка-и-общий-каталог--ux-47).
