# Импорт PDF HansLaser

Локальная реализация 17.10.2026: профиль `hans-pdf/v1`, отдельный нормализатор и подключение к форме новой заявки. Поддерживается текстовый PDF. Импорт читает документ и подготавливает форму; INSERT выполняется только по обычному действию пользователя после проверки полей/цены. Рабочая MDB и схема не меняются при разборе.

## Принцип вместо фиксированных строк

Старый `Form1.Button_RunClick` разбивал плоский текст по переносам и выбирал строки `[10]`, `[11]`, `[13]`, `[15]`, `[16]`, `[17]`, `[25]`/`[30]`. Материал делился по первому `_`; перенос имени или дополнительный `_` могли изменить смысл полей. Новая реализация сохраняет смысл/расчёты, но эти индексы не переносит.

`DocumentReader` использует уже подключённый PdfPig: слова и их прямоугольники в координатах страницы. Профиль собирает визуальные строки с допуском, зависящим от высоты текста; порядок объектов PDF не определяет порядок полей. Колонки и границы ячеек вычисляются по подписям, а не абсолютным координатам конкретного отчёта.

| Поле | Источник |
| --- | --- |
| Номер/дата | Ячейка «Заказ» с идентификатором `yyyy-MM-dd-номер--HANSLASER.Dsp` / двойным дефисом перед номером. Поддержан перенос идентификатора; ведущие нули сохраняются. В журнале `MMdd-номер`. Дата формирования с `@` и внешнее имя файла не выбирают значения. |
| Вид резки | Явная метка HANSLASER в идентификаторе внутри поля заказа. При неизвестном заголовке поле пустое. |
| Итоговые листы/детали/пробивки/вес/длина/время | Верхний блок по соответствующим подписям. «Использованная площадь» ограничивает соседнюю ячейку, но не становится весом/количеством. |
| Габариты/толщина | Колонки «Размер X», «Размер Y», «Толщ. (мм)» таблицы листов. Размер для прежнего журнала — `YxX`. Несколько размеров одной толщины — через запятую без повторов, до 255 символов. |
| Количество по раскладке | Колонка «К-во», положительное целое. Сумма всех строк сверяется с итогом «Листов». Колонка «№», в том числе `1, 1`, в подсчёте не участвует. |
| Материал и ID | Колонка «Материал». Отделяется последний подтверждённый суффикс `_0`, `_1`, `_2`, `_-1`; дополнительные `_` в марке сохраняются. Неизвестный ID требует проверки, исходная строка материала не усечена по догадке. |
| Газ | Колонка Gas/Газ; сохраняется текст, по ID не угадывается. O2/N2 — наблюдаемые варианты, не закрытый список. |

Таблицы «Детали», продолжения детализации, примечания, дата печати и номера страниц не подменяют реквизиты/итоги. Продолжение таблицы листов на следующей странице распознаётся по повторённым заголовкам колонок. Равные повторные значения допустимы; разные номера заказов, материалы, ID или газы дают ошибку соответствующего поля. Разные толщины, невалидные размеры/количества и превышение длины поля также диагностируются. Полный нормализатор отказывает при ошибках, форма сохраняет достоверные поля и оставляет сомнительные пустыми.

Источники представлены общим `SpecificationValueSource`: `HtmlValueSource` сохраняет таблицу/строку/ячейку, `PdfValueSource` — страницу, прямоугольник, подпись и исходный текст. В JSON инструмента у источников есть `Kind` Html/Pdf; это диагностический формат вне MDB. Подсказки формы показывают происхождение значений.

## Совместимость расчётов и сохранения

- Длина HansLaser: прежние **Double и `Ceiling(мм / 1000)`**, без `+1` БЛОК. Для 1000 мм — 1 м, для 1000,001 мм — 2 м. Переполнение Int32 диагностируется.
- Коэффициент — общий `CalculatePunchCoefficient` по итоговым деталям/пробивкам, с прежними Double/ToEven. Количество листов не добавляет множителей.
- Выбор прайса прежний: ID 1 → `PriceHL_id1`, ID 2 → `PriceHL_id2`, ID 0/-1 → `PriceLL500`. Импортированный HansLaser с пустым/неизвестным ID не получает предварительный расчёт и не сохраняется до ручной проверки. Явный `-1` остаётся способом выбрать стандартный прайс; поведение ручного ввода без импорта не меняется.
- Газ при таком импорте также нужно заполнить перед сохранением. Пользователь может исправить поля; исходный отчёт остаётся доступен в диагностике.
- Сохранение использует существующий `ManualOrderDraft`, прайс/транзакцию/проверку конфликта. В составном `Коэффициент` сохраняются прежние `коэффициент|детали|пробивки|ID|газ`. Новых полей/таблиц MDB нет.
- Длительность с произвольным числом часов остаётся справочной; неверная/отсутствующая длительность — предупреждение. В MDB она не записывается.

## Использование и диагностика

Один PDF можно перетащить на главное окно либо выбрать через «Выбрать спецификацию». Сохраняются отмена/Escape, защита ввода при замене параметров и после неизвестного commit. Менеджер/заказчик заполняются вручную. Повреждённый PDF не стирает прежний ввод; документ без доступного текста получает пояснение об отсутствии текстового слоя. Автоматического OCR/загрузки в облако нет.

```bash
./scripts/dotnet.sh run --project tools/Jornal.Inspect -- hans-spec "/путь/спецификация.pdf"
```

JSON содержит отчёт/источники и нормализованную заявку при полном разборе; код 1 — хотя бы один неполный/ошибочный документ. Реальные данные сохранять только в `.local/` или другой закрытой папке.

## Проверка и границы

Частный корпус из 60 PDF/66 страниц сверяется с независимой выгрузкой Poppler, подготовленной до реализации профиля: все поля нормализатора, исходные длина/вес/время, количество раскладок и неизменность SHA-256. Путь к закрытому JSON-манифесту задаётся `JOURNAL_HANS_SPEC_MANIFEST`; без него соответствующие проверки явно пропускаются. Реальные файлы/ожидания не входят в Git.

Публичные синтетические проверки покрывают дополнительные `_`, ID/газ, перестановку колонок/объектов, масштаб/сдвиг, перенос номера, ведущие нули, несколько размеров/страниц, ложные подписи в деталях, пропуски/конфликты, отказ от стандартного прайса при неизвестном ID, округление и отсутствие текстового слоя. Настоящий синтетический PDF проходит PdfPig → профиль → форму → явное сохранение прежних сегментов. Routed drag/drop и обе темы проверяются в Avalonia Headless.

Локальная проверка 17.10.2026: Release-сборка всего решения без предупреждений/ошибок, 478 тестов прошли, 10 зависящих от Windows/дополнительных источников проверок явно пропущены. Включены оба частных корпуса: 31 HTML и 60 PDF. Хеши всех 60 PDF после работы совпали.

Поддержка этих шаблонов не означает распознавание произвольного PDF. Новый вид отчёта требует образца и расширения профиля. Вставка текста/OCR/пакетный импорт остаются отдельными этапами. Нативный DnD из Windows Explorer, старый EXE и запись в сетевую MDB требуют ручной проверки на копии; Linux и Headless её не заменяют.
