# Обновление журнала — UX-69/71/72

Поручено пользователем 18.10.2026. «Настройки → Общие → Журнал → Автоматически обновлять журнал», по умолчанию включено, в том числе для старого профиля без параметра. Выбор локальный (`UiPreferences.AutomaticJournalRefresh`), переживает запуск/обновления/сброс компоновки. Новые разделы не добавлены. Работа локальная, без push/PR/релиза.

## Обнаружение изменений

- `JournalFileWatcher` наблюдает только выбранный файл, без подкаталогов: LastWrite/Size/FileName, Changed/Created/Deleted/Renamed/Error. Это сигнал возможного изменения файла, не уведомление о commit/конкретной заявке. Запись старым EXE также может вызвать сигнал, без его доработки и без новой схемы MDB.
- Подписка создаётся вне UI-потока. События объединяются в один отложенный вызов UI; серия ждёт 3 секунды тишины, но непрерывные события не отодвигают чтение бесконечно. Между завершёнными попытками минимум 15 секунд, одновременно выполняется одно фоновое чтение.
- Каждые 5 минут после последнего успешного чтения, включая явный F5 выполняется контрольный запрос данных. Размер/LastWriteTime не заменяют сверку содержимого; неподдерживаемое наблюдение её не отменяет.
- После ошибки наблюдения подписка пересоздаётся с паузой 30 секунд; неудачная попытка подписки повторяется через 5 минут. Успешная подписка помечает данные для сверки, закрывая промежуток подключения. Поздние события старого источника/старой подписки игнорируются.
- После показа/разворачивания окна данные помечаются для обновления с прежним ограничением частоты. В скрытом/свёрнутом окне новые запросы не начинаются; видимое неактивное окно продолжает обновляться; наблюдение собирает необходимость обновления.
- Деможурнал не наблюдается. Linux JSON-копия поддерживает замену файла; уведомления Linux для удалённой SMB-папки не гарантируются, контрольное чтение остаётся.

## Состояние пользователя и безопасность

Фоновое чтение откладывается, пока удерживается кнопка мыши или другой указатель:
оно не должно кратко отключить кнопку между нажатием и отпусканием и отменить
клик. Это распространяется и на изменение размеров панелей. После отпускания
координатор продолжает обработку накопленных сигналов. Движение мыши без кнопок
после отменённого захвата и деактивация окна снимают защиту от незавершённого
жеста; видимое неактивное окно по-прежнему обновляется. Ручной F5 не меняется.

Открытые выпадающие списки/фильтры, меню таблицы/результата, календарь и фокус в редакторе непустого письма активного окна также откладывают чтение: черновик фильтра или ввод текста не должны прерываться фоновым запросом.

Фон читает выбранный день либо историю при «Все даты»/глобальном поиске через прежний backend. У `OrderDurationPreparingReader` используется `ReadSnapshotAsync`: **только чтение, без запуска/повтора подготовки схемы**. Таблиц/полей, отметок изменения и записей в MDB механизм не создаёт.

При открытом дочернем окне (новая/редактируемая заявка, пакет, прайсы, корзина, настройки), импорте, записи, копировании, незавершённом вводе поиска, настройке экрана и контекстном меню чтение откладывается. Ожидающие изменения сохраняются. Во время запроса запись из главного окна недоступна; F5/смена периода могут отменить и заменить чтение. Поколение запроса/токен защищают от позднего ответа после отмены, отключения, закрытия или смены источника.

Фильтры, поиск, ручная сортировка и письмо сохраняются. Выбор восстанавливается по ID среди оставшихся видимых строк. При равном видимом снимке Reset таблицы не отправляется. После фонового чтения дня старая история отбрасывается; следующий глобальный поиск читает её заново. Изменение/удаление заявки из сформированного результата даёт короткое предупреждение, текст не переписывается.

Неизвестный исход записи (`RequiresReload`) и неуспешная явная загрузка другого периода требуют прежнего ручного F5. Фон не подтверждает commit, не повторяет запись и не снимает блокировку.

Ошибка оставляет список, выбор, письмо и прежние сообщения действий. В строке времени появляется «Автообновление недоступно», без модальных окон; успех возвращает обычное время. Повторные попытки задерживаются на 15/30/60/120/240/300 секунд, события не обходят паузу. Токен запроса отменяется через 30 секунд; завершение синхронного OLE DB зависит от драйвера, поздний ответ не применяется. Отключение/закрытие отменяют запрос и освобождают наблюдение. Таймер окна останавливается при закрытии, при выключенной настройке ничего не запрашивает.

Транзакции, сравнение исходных снимков, проверки прайса/конфликтов не меняются. Общая блокировка всех клиентов не добавляется: используются прежние соединения Jet, временный отказ чтения обрабатывается повтором. Событие файла не доказывает видимость всех кешированных изменений Jet.

## Проверка и границы

UX-73 использует штатный Fluent-шаблон строки; копия ради бокового индикатора удалена по итоговому решению пользователя. JournalSelectionCell меняет только фон служебного столбца. Собственный шаблон самой таблицы для восстановления прокрутки остаётся; его нужно сверять при обновлении Avalonia. Контракт — [контрастность строк](row-appearance.md).

### Первичный аудит 18.10.2026 — история выявленных замечаний

По запросу пользователя выполнен анализ без правок производственного кода. Изолированный Headless-прогон на 200 искусственных заявках подтвердил три недочёта первоначальной реализации:

1. `RefreshAutomaticallyAsync` использует общий `IsLoadingOrders`: таблица отключается на время чтения и теряет клавиатурный фокус, который не возвращается даже при неизменном снимке. Нужны отдельное состояние фонового чтения и сохранение возможности навигации без пересечения с записью.
2. При изменении данных общий Reset/повторное назначение SelectedItem сохраняет выбранный ID, но возвращает вертикальную прокрутку: в первичном эксперименте значение ползунка изменилось 600 → 0 при сохранённой одной выбранной строке. Повторная проверка ниже дополнительно измеряет фактическую видимую строку и её координату, поскольку одного Value недостаточно. Нужно сохранять видимый якорь/смещение либо обновлять строки без общего сброса.
3. Координатор не учитывает успешный ручной F5. При отмене незавершённого фонового запроса ручное чтение завершается, затем следующий тик немедленно запускает ещё одно: счётчик чтений 2 → 3 (F5) → 4. Нужно согласовать ручное/фоновое чтение и учитывать успешно прочитанный снимок, сохраняя сигналы новых изменений во время запроса.

Замечания исправлены локально следующим этапом UX-71, описанным ниже. Артефакты анализа — игнорируемые `.local/auto-refresh/audit/` и `audit.log`, без рабочих MDB/личного профиля. Уведомления + резервная сверка остаются разумной архитектурой; эти наблюдения относятся к её интеграции с UI/ручным обновлением. Операций записи/подготовки схемы в фоновом пути не обнаружено, но это не гарантия отсутствия любых регрессий и не замена нативному Jet/SMB-прогону. Перед выпуском проверить совместную работу старого EXE/новых клиентов на копии MDB в общей папке Windows.

Тесты: серия событий/ограничение частоты, резервное чтение без события, свёрнутое/занятое окно, событие во время запроса, отказ/восстановление наблюдения, задержка повтора, отмена/смена источника, реальные уведомления временного файла и атомарная замена. Отдельно — выбор/фильтры/сортировка/письмо, неизвестный commit, отсутствие подготовки схемы, обе темы/сохранение профиля.

В Windows-контур добавлены параллельные читатели и запись цвета другим клиентом с проверкой остальных данных/схемы. На Linux тест пропускается. Реальная общая папка, кэширование SMB/Jet, совместная работа старого EXE и нескольких новых клиентов требуют отдельного прогона Windows; Linux/headless этого не доказывают. Рабочая MDB, спецификации и личные настройки разработчика не меняются.

Локальная проверка 18.10.2026: полный `scripts/check.sh` — 1239 успешных сценариев, 16 необязательных пропусков, 20 Python-проверок; 68 нативных Access-проверок пропущены на Linux. Уточнение паузы при открытом фильтре проверено отдельным набором из 96 связанных сценариев; окончательный набор всех 35 новых сценариев, включая фильтр и ввод письма, успешен. Обе темы/размеры настроек просмотрены на снимках, навыки валидны, `git diff --check` чистый. Логи — игнорируемая `.local/auto-refresh/`. Сборки Release/Debug без предупреждений/ошибок. Без push/PR/релиза.

## UX-71 — одинаковое поведение F5, кнопки и фона

При повторном чтении того же запроса `IsRefreshingOrders` блокирует запись, но не отключает таблицу: можно прокручивать, менять выбор и сортировку. Первичная загрузка/другой контекст остаются отдельным `IsLoadingOrders`. Фокус в поиске/письме не перехватывается; нажатие кнопки обновления не переносит фокус в таблицу принудительно.

Непосредственно **перед применением ответа** сохраняются выбранные ID, текущий столбец, наличие фокуса в таблице, первый видимый ID и смещение его верхней границы относительно области строк, горизонтальная прокрутка и прежний порядок видимых ID. Сетевой запрос не фиксирует устаревший выбор/прокрутку: изменения пользователя во время ожидания учитываются.

- Новые строки выше якоря и изменение позиции выбранной записи при сортировке не сдвигают содержимое под глазами к выбранной строке.
- Если якорь исчез, берётся следующая сохранившаяся строка прежнего порядка, иначе предыдущая. Это якорь **прокрутки**, не новый выбор; границы списка естественно ограничивают смещение.
- Исчезнувшие/больше не подходящие фильтрам ID исключаются из выбора. Соседняя запись автоматически не отмечается. В строке обновления кратко «Из выбора исключено: N», без неподтверждённого утверждения об удалении. Новый выбор и следующее успешное чтение снимают отметку; ошибка не возвращает уже снятую отметку.
- Равный видимый снимок не отправляет Reset. Поиск, дата, фильтры, ручная сортировка и письмо сохраняются. Подлинная смена запроса/даты/фильтра очищает выбор, отменяет прежний запрос и игнорирует его поздний ответ.
- При ошибке остаются прежние строки/выбор/позиция/фокус/письмо. Неуспешная смена периода и неизвестный commit по-прежнему требуют успешного явного F5; фоновое чтение не снимает эту защиту.

Координатор получает начало и результат явного чтения. Успех подтверждает только накопленные **до начала** запроса сигналы и откладывает пятиминутную сверку. События во время запроса сохраняются, следующее чтение соблюдает минимум 15 секунд. Отменённый фон не запускает сразу лишний запрос после успешного F5; устаревшее завершение другого явного запроса игнорируется.

В Avalonia DataGrid значение `ScrollBar.Value` само по себе не перемещает строки. `JournalScrollBar.ScrollTo` дополнительно вызывает защищённый `OnScroll(ThumbTrack)`. Собственный `JournalOrdersGrid` основан на Fluent-шаблоне DataGrid 12.1.2 с заменой типов двух полос; остальные части/ресурсы и общие узкие полосы сохранены. При обновлении пакета сравнивать этот шаблон с оригиналом. В приложении нет обращения к приватным полям или рефлексии Avalonia.

Регрессии проверяются по реальному ID и координате верхней строки, а не только по числу ползунка: DataGrid может уточнять оценочную высоту виртуализированного списка. В повторном изолированном прогоне сохранены ID 160 и Y=-11 px после замены снимка; фокус/доступность остаются, счётчик после замены фона F5 — 2 → 3 → 3. Тесты `JournalReadContextTests`, `AutomaticJournalReadTests` и `JournalAutoRefreshTests` покрывают обе темы, 100/150/200%, вставку сверху, исчезновение якоря/выбора, перемещение по числовой сортировке, горизонтальную прокрутку, свежий выбор во время ожидания, ошибки и поздние ответы.


### Промаргивание команд при коротком чтении

`CanBrowseJournal` отделён от разрешения записи: фильтры столбцов/статуса, снятие выбора, чекбоксы и сортировка не меняют доступность только из-за перечитывания того же контекста. Открытие фильтра отменяет ожидающий ответ до начала черновика, поэтому ответ не закрывает меню и не теряет выбор пунктов.

Блокировка операций записи остаётся немедленной. Для ранее доступных `JournalButton` обычная непрозрачность удерживается первые 300 мс (`read-refresh-pending`), чтобы быстрый запрос не затемнял/высветлял всю панель и иконки. При более долгом чтении возвращается стандартный вид недоступной команды. Изначально недоступные команды сохраняют свой вид; изменение выбора во время ожидания снимает отсрочку. Таймер/классы снимаются при завершении, отмене, смене модели и закрытии окна. Настройки/анимации/искусственная задержка чтения не добавлены.


Проверка UX-71, 18.10.2026: `scripts/check.sh` прошёл — Release без предупреждений/ошибок, 1267 успешных тестов, 16 необязательных пропусков и 20 Python-проверок. Все 68 нативных Access-тестов штатно пропущены на Linux; Jet/SMB/старый EXE этим не подтверждены. После добавления лицензии собственного варианта шаблона и проверки цветов ещё 8 целевых Release-сценариев прошли: обычные цвет/фон/непрозрачность кнопок на коротком чтении, ранее недоступные команды, длительное чтение и Full HD обеих тем. Светлый/тёмный снимки 1920 px просмотрены, полосы занимают свой участок. Debug для F5 также собран без предупреждений/ошибок. Артефакты — игнорируемая `.local/refresh-context/`; рабочие MDB/спецификации/личный профиль не изменялись, без push/PR/релиза.


### Пустой результат не приостанавливает фон

В пользовательском прогоне Linux сегодняшний список оставался пустым после внешнего изменения JSON-копии. Проверены актуальность запущенной Debug DLL, путь профиля и подписка inotify на тот же каталог. Переход из поля результата в поиск без ввода/F5 возобновил чтение, но одновременно передал окну активацию. Поэтому ответ пользователя сам по себе не разделял влияние двух условий. Независимая регрессия подтвердила ошибку пустого редактора; следующий полевой прогон отдельно подтвердил избыточную проверку активности окна (UX-72 ниже).

Исправлено: `ResultTextBox.IsKeyboardFocusWithin` откладывает чтение только вместе с непустым `ResultText`. Пустая строка и одни пробелы паузой не считаются. Непустое письмо сохраняет прежнее правило; общий путь применения снимка сохраняет фокус, текст и день. Регрессия `EmptyTodayRefreshesWithFocusInAnEmptyLetter` воспроизводит внешний сигнал файла, пустой сегодняшний список и фокус в пустом/пробельном редакторе; прежний сценарий защищает ручной ввод непустого письма.

Проверка поправки пустого результата: 54 целевых Release-сценария прошли, включая два новых прогона пустого дня/пустого и пробельного письма с настоящим таймером/сигналом файла. Непустой текст по-прежнему откладывает фон. Запущенную пользовательскую Debug-сборку не перезаписывали; исправление попадёт в неё при следующем F5 с обязательной сборкой.


## UX-72 — видимое окно и разворачивание

Новый полевой прогон отдельно показал: внешняя смена цвета читалась после активации Journal, хотя курсор уже находился в поиске. Причина — передача `IsActive` в координатор. Готовность окна изменена на `IsVisible && WindowState != Minimized`; потеря активности при работе в другой программе не приостанавливает видимый журнал. Открытые дочерние окна, запись, меню, незавершённый поиск и прежние ограничения остаются. Фокус непустого письма удерживает паузу только в активном Journal; сам текст никогда не заменяется чтением.

В скрытом/свёрнутом окне новые запросы не стартуют, сигналы изменений сохраняются. После показа/разворачивания координатор сам помечает данные для сверки, даже если событие файла потерялось, и не ждёт пятиминутного срока. Пауза объединения событий при возврате уже пройдена; минимум 15 секунд между попытками и сетевой backoff сохраняются. При сохранении/открытой форме запрос ждёт безопасного момента. Переключение между видимыми приложениями само по себе больше не порождает дополнительное чтение при каждом возвращении.

`JournalTableContext` не вызывает восстановление клавиатурного фокуса неактивного окна. Это дополняет прежнюю защиту положения/выбора: обновление не должно переключать пользователя из другой программы в Journal.

Проверка: сценарий с настоящим LocalJournalStore, внешней атомарной заменой JSON и неактивным видимым окном на прежнем коде оставлял исходный цвет после 20 секунд. После исправления тот же сценарий обновляет значение и реальный фон строки; второй вариант подтверждает сохранение прежнего цвета при Minimized и чтение после Normal.
