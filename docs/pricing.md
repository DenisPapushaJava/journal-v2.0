# Прайсы и расчёт цены

Уточнение 18.10.2026: существующие толщины разрешено изменять отдельным подтверждаемым переименованием (UX-54). Это исключение из первоначального запрета менять имена тарифных колонок; Orders, типы/ключи, формулы и исторические суммы сохраняются. Доработка фиксированного списка старого EXE остаётся отдельной задачей.

Модуль читает существующие прайсы и рассчитывает цену при создании/редактировании заявки. [Сохранение и сценарий проверки](manual-orders.md). В отдельной Linux-копии используется снимок перенесённых прайсов ([локальная копия](linux-local-copy.md)). Просмотр журнала использует историческую `Стоимость` и не пересчитывает её. Локально добавлено окно просмотра/редактирования прайсов — контракт ниже; опубликованная alpha.6 его ещё не содержит.

## Живой предпросмотр стоимости — 19.10.2026

По поручению пользователя большая кнопка «Рассчитать» удалена из нижней панели
новой заявки и редактора. Справа постоянный блок стоимости и короткая формула;
в пакете цена каждой карточки. Малый значок «Обновить тарифы» у цены, кнопка
в шапке пакета и прежний значок обновления толщин используют один путь обновления.

Автопредпросмотр запускается после паузы 300 мс при изменении станка, толщины,
целой длины, коэффициента, ID встроенного HansLaser, после импорта и загрузки
соответствующего прайса. Материал по имени, дата, номер, менеджер, заказчик,
размер/количество листов, вес, время, гибка и комментарий не входят в формулу.
Для новых станков ID HansLaser сохраняется как метаданные, но отдельные встроенные
прайсы не выбирает. Неполные числовые поля показывают «—» без преждевременной
красной проверки; цена не требует заполненного менеджера/заказчика. Нет тарифа —
прежняя ошибка толщины/цены и переход в Прайсы; нулевой тариф остаётся действительным.

Локальный расчёт использует тот же CuttingPriceCalculator и уже загруженный
ThicknessPriceSource.TryGet. На каждую цифру запрос в MDB не выполняется.
Смена станка/ID получает соответствующий прайс, общая форма/пакет делят task
по таблице. Явное обновление ждёт начатое чтение, затем один раз сбрасывает кэш
и обновляет цены всех карточек; возврат из прайсов также инвалидирует предпросмотр.
Новая цена подтверждается вместе с теми же полями таблицы и прежним Double/ToEven.

PricePreviewScheduler использует TimeProvider, не более одного ожидающего ITimer
на форму/карточку и поколение для callback в Dispatcher. Новый ввод, показ
подтверждённой цены, закрытие/смена модели и удаление карточки отменяют таймер.
Поздний callback не меняет закрытую форму. Удаление карточки не останавливает
общий источник других карточек. Автопредпросмотр не включает IsBusy и не отключает
ввод; перед быстрым сохранением ожидающий локальный расчёт выполняется сразу.

Редактор при открытии показывает сохранённую цену и не создаёт правку/ExpectedQuote.
Изменение комментария, заказчика и остальных полей вне формулы сохраняет точную
историческую Currency, включая NULL, без чтения/применения нового тарифа при записи.
Новая цена появляется после изменения параметров, замены спецификации либо
явного «Обновить тарифы» и включается в прежний diff. Возврат параметров к исходным
снимает автоматическую цену и соответствующую правку; явно обновлённая цена
сохраняет своё намерение. Неудачный необязательный refresh без изменения параметров
не запрещает сохранить комментарий с прежней ценой.

OrderEditChange.PriceParametersChanged/RequiresPriceCalculation — вычисляемые
JsonIgnore-свойства, без нового поля MDB/DTO. Все адаптеры, включая Jet, пропускают
чтение тарифа и возвращают Values.Price при отсутствии изменений формулы и
ExpectedQuote. Снимок заявки, привязка станка, типы/необязательные данные и read-back
по-прежнему проверяются. Клиент AccessHost отклоняет неожиданное изменение цены
в таком ответе как OutcomeUnknown. Ручного редактирования Price не добавлено.

Для новой/пересчитываемой заявки предварительная проверка читает свежий тариф;
если просмотренная цена отличается, запрос записи не отправляется, новая сумма
показывается и требуется повторное явное сохранение. Изменение тарифа между этой
проверкой и транзакцией по-прежнему останавливает запись/пакет, а не применяется
молча. Повтора записи по таймеру нет. Прайсы/Orders/форматы коэффициента и спецификаций
не меняются; Windows-пакет обязан содержать согласованные клиент и x86-хост.

Проверки — LivePricePreviewTests с управляемыми часами (без ожиданий по 300 мс),
пакет/удаление карточки, обе темы реальных окон, прежние dirty/missing-tariff/import
сценарии; NativeMaintenanceTests проверяют сохранение при NULL-тарифе и отказ
изменённой формулы. Это не подтверждение Windows/Jet/SMB на Linux.
Локальная проверка: scripts/check.sh — 45 release-проверок, Release без
предупреждений/ошибок, 1498 тестов успешны, 16 частных/платформенных пропущены.
Все 70 нативных Jet-тестов пропущены на Linux. После уточнения подписей и
форматирования формулы повторно собран весь проект (0 предупреждений/ошибок),
прошли 87 целевых проверок окон/толщин/предпросмотра. Логи —
.local/live-price-final-check.log, .local/live-price-final-build.log,
.local/live-price-final-ui.log; снимки обеих тем — .local/live-price-screenshots/.
Windows/Jet/SMB и установленный x64→x86 хост этим Linux-прогоном не подтверждены.
Локально без push/PR/релиза.

## Источник тарифа

`IPriceReader` читает одну выбранную таблицу. Windows использует OLE DB; установленное приложение передаёт запрос своему хосту x86 к системному Jet. Linux использует MDB Tools только для чтения. При каждом запросе читается текущая первая строка, как в старом `NewOrd/Edit`; дополнительные строки не суммируются и не подменяют первую. В режиме MDB общего снимка всех таблиц и долговременного кеша нет. Отдельная Linux-копия хранит явный снимок шести прайсов на момент импорта; он не обновляется автоматически из MDB.

| Вид резки | Таблица |
| --- | --- |
| Лазер | `PriceLL500` |
| Плазма | `PriceP` |
| Газо-кислородная | `PriceG` |
| HansLaser, ID строго `1` | `PriceHL_id1` |
| HansLaser, ID строго `2` | `PriceHL_id2` |
| HansLaser, остальные ID/без ID | `PriceLL500` |

Уточнение пользователя 18.10.2026: прежние фиксированные пределы толщины (лазер до 20 мм, плазма 2–32 мм, газовая резка 16–200 мм, HansLaser до 60 мм) устарели и сняты в новом приложении. Для любого станка доступна положительная толщина с заполненным неотрицательным тарифом в выбранном прайсе. Это правило общее для списка, проверки формы, расчёта и окончательной проверки при записи, включая пакет. Отсутствующий тариф по-прежнему блокирует расчёт и сохранение. Схема MDB, формула, выбор таблицы по станку/ID и исторические цены сохраняются; ограничения старого EXE автоматически не меняются.

`PriceLM500` доступна для чтения/диагностики, но прежний код создания/редактирования её не выбирает. Название материала не ограничивается справочником и не используется вместо ID. ID не нормализуется молча: `01` и ` 1` не превращаются в `1`.

При read-only исследовании свежего образца MDB 17.10.2026 дополнительно обнаружена таблица `PriceHL`: всего `Orders` и семь таблиц прайсов, в каждом прайсе одна строка. `PriceHL` не входит в фиксированный список `PriceTables.All`, и обращений к ней в исследованном старом/новом коде нет. Её наличие не означает использование в расчёте; автоматически подключать или удалять её нельзя. `PriceLL500` используется совместно обычным лазером и веткой HansLaser без ID `1`/`2`, поэтому изменение его тарифов затронет оба варианта. Хеш исходного файла при исследовании не изменился.

Колонка выбирается по числовой толщине; запятая/точка и конечные нули нормализуются, исходное имя сохраняется в расшифровке. Несколько колонок одной толщины дают ошибку вместо случайного выбора. Отсутствующая таблица, пустая таблица, отсутствующая колонка и NULL не становятся нулевой ценой. Настоящий нулевой тариф допустим; отрицательный тариф читается как есть, но расчёт блокируется. Значение должно помещаться в Long Integer и быть целым.

В MDB Tools некоторые числовые заголовки с запятой выводятся без кавычек. Поэтому **прайсы экспортируются с табуляцией**, а `Orders` сохраняет прежний CSV-контракт. Нет восстановления заголовков по количеству значений. После первой строки остаток stdout вычитывается с ограниченным буфером, чтобы большой экспорт не заблокировал дочерний процесс. Процессы имеют тайм-аут и отмену.

## Совместимость расчёта

Уточнение 18.10.2026: формы используют `CalculateResult` / `CalculateResultAsync` для ожидаемых отказов. Отсутствующая колонка, пустая первая строка или NULL тарифа возвращают причину со станком и толщиной, например «ГАР: нет тарифа для 12 мм. Добавьте его в „Прайсы“». В обычном сценарии это не исключение и не технический отчёт. Отрицательная цена и переполнение также имеют результат отказа. Строгие `Calculate` / `CalculateAsync` сохраняют `PriceCalculationException` для существующих потребителей и окончательной проверки записи; Double/ToEven, Currency и реальный нулевой тариф не меняются.

Перед добавлением формы проверяют цены без записи. Пакет читает каждую нужную таблицу и каталог станков один раз на эту проверку; между действиями снимок не сохраняется. При ошибке весь пакет остаётся в форме. После успешной проверки создание/редактирование по-прежнему повторно читает прайс в операции записи и сверяет предварительную цену: проверка UI не заменяет транзакцию и не устраняет возможный конфликт с другим клиентом. Контракт AccessHost и схема MDB не изменены этим исправлением.

Цена: `Math.Round((double)тариф * целые_метры * (double)коэффициент, MidpointRounding.ToEven)`. Порядок операций и Double сохранены из старого кода: замена на decimal-арифметику меняет отдельные результаты на границе округления. Синтетический пример: тариф 1, длина 25, коэффициент 2,3 дают 57 по старой формуле и 58 при decimal-арифметике. Изменение этого поведения требует отдельного решения.

Результат возвращается как decimal для сохранения в Access Currency, с проверкой диапазона. Минимум 500 ₽ существует только в формате результата для письма. Вес и количество листов не добавляют множителей. Длина передаётся **целым числом метров**, уже подготовленным вводом/импортом: правила перевода миллиметров подключены в отдельных нормализаторах БЛОК и HansLaser (прежний Double/Ceiling), повторного округления длины здесь нет.

Автоматический коэффициент: сначала округление `пробивки / детали` к чётному, затем прежняя ступенчатая шкала 1–3 из `CalculationCoefficient`. Нулевое/отрицательное число деталей и отрицательные пробивки отклоняются. Ручной коэффициент должен быть положительным. Неизвестный исторический коэффициент не подменяется единицей.

## Выбор толщины в заявке — 18.10.2026, UX-51

В новой заявке, редакторе и каждой карточке пакета толщина выбирается из закрытого списка текущего станка. Источник — реальные тарифы первой строки его прайса: NULL и отрицательные значения исключены, настоящий нулевой тариф допустим. Порядок числовой, по возрастанию; дополнительных фиксированных границ станка нет. Выбор таблицы HansLaser по ID материала сохранён; для нового станка используется его собственный прайс. Неизвестный ID импортированной HansLaser-спецификации блокирует подбор до ручной проверки ID, без чтения запасного прайса.

Импортированное или историческое значение без доступного тарифа остаётся видимым с ошибкой. Оно не заменяется ближайшей/первой толщиной; сохранение включённых позиций блокируется. Численно равные записи вроде `2,50` и `2,5` сопоставляются без переписывания исходного ввода. Пользователь может выбрать допустимую толщину либо открыть нужный прайс кнопкой у поля. Прайсы открываются поверх формы; после закрытия каталог/толщины обновляются, остальные поля и карточки сохраняются.

Снимок прайса общий только для открытой формы/пакета. Смена станка/ID запрашивает соответствующий список; явное обновление тарифов и возврат из прайсов перечитывают снимок. Поздний ответ предыдущего станка не меняет новый список. Загрузка блокирует выбор толщины и сохранение, остальные поля и добавление спецификаций остаются доступны. Удаление одной карточки отменяет её ожидание, сохраняя общий запрос других карточек; закрытие формы отменяет чтение. Повторное открытие сохранённого ввода создаёт новый источник чтения.

Сбой чтения имеет отдельную причину и кнопку повтора, не подменяется сообщением об отсутствии тарифа. Исходная толщина сохраняется; допустимость не считается подтверждённой. Проверка актуального тарифа перед записью и внутри транзакции остаётся обязательной: список в UI не заменяет защиту от изменения прайса другим клиентом. Схема/значения MDB и формулы этим изменением не меняются.

Проверки: числовой порядок, NULL/ноль, тарифы вне прежних границ, смена ID/станка и запоздавший ответ, отказ/отмена/повтор/переоткрытие, общий источник пакета, запрет сохранения отсутствующего тарифа. Headless-окна создания/редактирования проверяют обе темы и сценарий правки прайса без потери ввода на синтетической локальной копии. Это не подтверждает Jet, старый EXE или SMB.

## Проверка без записи

На Linux для чтения нужен `mdb-export`; `JOURNAL_MDB_EXPORT` позволяет задать его путь. Команды разработчика:

```bash
./scripts/dotnet.sh run --project tools/Jornal.Inspect -- prices .local/копия.mdb
./scripts/dotnet.sh run --project tools/Jornal.Inspect -- price .local/копия.mdb HansLaser 2,5 25 2,3 2
```

`prices` выводит JSON первой строки каждого из шести прайсов; ошибка одной таблицы не скрывает результаты остальных и даёт ненулевой код завершения. `price` читает только нужный прайс и возвращает таблицу, колонку, тариф, метры, коэффициент и итог. Обе команды только читают файл. Вывод может содержать рабочие тарифы: его не следует добавлять в публичный Git. На Windows инструмент разработки вне установленного комплекта требует OLE DB своей разрядности; поставляемый хост x86 проверяется отдельно в installer CI.

Проверки покрывают выбор станка/ID, положительную толщину и наличие тарифа вне прежних границ, реальные границы Double/ToEven, шкалу коэффициента в сравнении с исходным классом WinForms, NULL/ноль, неоднозначные колонки, первую строку и отмену. Windows CI обязательно читает искусственные прайсы через Jet x86 и через поставляемый хост из клиента x64, проверяет неизменность MDB. Сверка на Linux с сохранённым образцом и текущей копией: по шесть таблиц и 142 тарифа на файл совпали с независимой выгрузкой, по пять расчётов совпали с прежней формулой; хеши файлов сохранились. Это не проверка старого EXE и параллельной работы по SMB.

## Просмотр и редактирование прайсов — 17.10.2026, UX-46

Кнопка «Прайсы» рядом с колокольчиком открывает отдельное окно для текущего источника. «Настройки → База данных» по-прежнему отвечает за подключение. Слева — четыре прежних вида резки и «Прочие прайсы», справа — толщины по возрастанию и тарифы в ₽/м. HansLaser выбирает базовый/ID 1/ID 2. Каталог `PriceCatalog` явно связывает базовый HansLaser и лазер с одним `PriceLL500`; копии тарифа не создаются. `PriceLM500` и `PriceHL` доступны только для просмотра; таблицы не активируются из-за имени или факта наличия. Отсутствующий дополнительный прайс даёт локальную ошибку выбранной страницы.

По кнопке «Редактировать» появляются отдельные колонки новой толщины и новой цены, счётчик правок и область действия изменения. Переключение прайса блокируется до «Сохранить»/«Отмена». Изменённые значения выделены, некорректный ввод блокирует сохранение; Ctrl+S сохраняет, F5 перечитывает. Закрытие с несохранёнными правками требует явного отказа от них. Пока выполняется запись, закрытие приложения и повторные операции заблокированы.

`PriceTableChange` / `IPriceEditor` принимают полный исходный снимок и новые значения тех же колонок. Новая цена — целые неотрицательные рубли в диапазоне Int32; пустое поле означает NULL, ноль остаётся настоящей нулевой ценой. Обязательность поля MDB сохраняется: попытка очистить обязательный тариф отменяет всю операцию. Типы и ключи существующих колонок сохраняются. Последующее уточнение 18.10.2026 разрешает явное изменение толщины с подтверждением (UX-54 ниже). По последующему уточнению пользователя допускается добавление новых колонок толщин — отдельный раздел ниже; удаления нет; явное переименование толщин разрешено последующим уточнением UX-54 ниже. Неизменённые исторические отрицательные тарифы не переписываются и по-прежнему не подходят для расчёта.

Windows использует `OleDbPriceEditor`, в установленном комплекте — операцию `UpdatePriceTable = 12`, добавленную в конец протокола 1. Только пять используемых прайсов могут изменяться. Прайс для записи должен содержать ровно одну строку, как в свежем образце: пустую/многострочную таблицу приложение не исправляет автоматически. В транзакции проверяются структура и полный снимок тарифов, выполняется типизированный UPDATE с условием по исходным значениям и контролем одной затронутой строки. Сохранённое представление проверяется до commit; после commit запросов нет. Конфликт/неизвестный исход сохраняют ввод и запрещают повтор до успешного обновления; автоматических повторов нет. Технические ошибки используют существующую диагностическую операцию AccessHost и стадии ReadPrices/WriteRecord/ReadBack/CommitTransaction, без тарифов и путей в отчёте.

Явное обновление после конфликта переносит только изменённые пользователем ячейки поверх перечитанного прайса. В колонке «Цена» видны актуальные значения, в «Новая цена» — ввод для ручной проверки; чужие изменения остальных тарифов сохраняются. Повторный «Сохранить» остаётся отдельным действием. При ошибке чтения или изменении структуры ввод сохраняется и запись остаётся заблокированной.

На Linux исходная MDB остаётся только для чтения; `LocalJournalStore` изменяет исключительно `.journal-test.json` под прежней межпроцессной блокировкой и атомарной заменой файла. Формат локальной копии остаётся прежним с шестью прайсами, `PriceHL` в старую копию автоматически не добавляется. В деморежиме тарифы меняются только в памяти сеанса через отдельный адаптер; прежнее создание демозаявок с неизвестной ценой сохранено, ложный предварительный расчёт не включается. Источник и область сохранения задаются явно, тарифы демонстрации не подставляются вместо недоступных прайсов выбранной базы. Рабочая MDB и пользовательская локальная копия при разработке не изменялись.

Правка тарифа не изменяет сохранённые суммы/поля заявок и минимум цены для письма. Создание/редактирование продолжают проверять просмотренную цену по действующему прайсу. Новые станки, создание новых прайсов и хранение каталога вне текущих привязок не входят в этот этап. Для гидроабразива согласован тариф за метр по толщине; коэффициенты, округление, импорт и совместимость нового вида со старым EXE требуют отдельного этапа.

Проверки добавлены в `PriceEditingTests`, `PriceEditorWindowTests`, `NativePriceEditingTests` и сценарий клиента x64 с упакованным AccessHost x86. Нативные Jet/старый EXE/SMB проверяются отдельно от Linux; наличие тестов не означает, что они прошли на этом компьютере.

Локальная проверка этапа: `scripts/check.sh` завершился успешно, 775 тестов пройдены, 15 частных/платформенных пропущены; 11 проверок выпуска успешны, Release без предупреждений и ошибок. Отдельные 49 нативных Access-тестов пропущены на Linux. Обе темы/минимальное окно просмотрены по Headless-снимкам, включая новые значения и отказ от несохранённых правок. Публикация/PR этого этапа не выполнялись.

## Экспорт прайсов в Excel — 18.10.2026, UX-52

В шапке «Прайсов» есть «Экспорт в Excel». Отдельное окно показывает участвующие в расчётах станки текущего каталога, включая пользовательские; каждый по умолчанию отмечен. «Прочие прайсы» (`PriceLM500`, `PriceHL`) в этом списке отсутствуют. При снятии всех отметок экспорт недоступен. Следующий шаг — системный выбор места/имени `.xlsx` с подтверждением замены существующего файла. Из режима несохранённых правок сначала требуется сохранить или отменить изменения: экспорт читает сохранённые тарифы.

По уточнению пользователя оформление простое и лаконичное: один лист на выбранный станок, название, дата выгрузки, «Толщина, мм» и «Цена, ₽/м». HansLaser содержит общую колонку толщины и три столбца: базовый, нержавеющая сталь, цветные металлы. Имена MDB-таблиц и ID не выводятся. Толщины числовые, по возрастанию; цены — числовые целые рубли за метр, выравнивание вправо. Пустая ячейка означает отсутствие тарифа, настоящий ноль сохраняется; исторические цены/полный состав толщин не фильтруются правилами формы заявки. Есть спокойная шапка, фильтр, закрепление заголовков и настройки печати; формул, макросов и внешних ссылок нет.

`PriceExportReader` использует только `IPriceReader`, читает каждый уникальный прайс один раз для книги (общий базовый лазер/HansLaser совпадает), затем формирует снимок. Это последовательные чтения, а не единая транзакция всех таблиц; при изменениях другим клиентом обновите прайсы и повторите выгрузку. Ошибка любого выбранного прайса останавливает всю выгрузку с названием проблемного станка/профиля. Данные, схема MDB и расчёты не изменяются.

`PriceWorkbookExporter` записывает небольшой SpreadsheetML/ZIP средствами .NET, без Office или новых NuGet-зависимостей. Имена листов ограничены правилами Excel и остаются уникальными; названия записываются как текст. Файл создаётся во временном файле рядом с назначением и заменяет его только после успешного создания всей книги. При сбое/отмене до замены прежний файл остаётся, временный удаляется. После завершённой замены отмена не откатывает сохранённый файл. Отказ доступа/открытый в Excel файл/недоступная папка показывают ошибку с возможностью повтора; отмена системного диалога оставляет выбор станков. Расширения кроме `.xlsx` не допускаются. Чтение/сохранение выполняются с отменой и двухминутным таймаутом, отсчёт после выбора пути.

Проверки: состав/отметки/общий прайс, только выбранные станки, сортировка и числовые типы, NULL/ноль, безопасные имена/текст, отмена/повтор/сбой без частичного результата, неизменность синтетического источника. Headless-окна проверяются в обеих темах и компактном размере. Синтетическая книга дополнительно прочитана openpyxl и открыта/отрендерена LibreOffice; установка Microsoft Excel, Windows-диалог сохранения и SMB остаются отдельным полевым прогоном. Локальная реализация, без push/PR/релиза.

## Добавление толщин — уточнение пользователя 17.10.2026

Пользователь разрешил новые произвольные положительные толщины по прежнему принципу хранения, а зашитый список старой формы допускает доработать отдельно. Это исключение из первоначального запрета расширения схемы: добавляются только столбцы в пять используемых прайсов. Существующие поля/типы/ключи/данные, Orders и формулы сохраняются; удаления нет; явное переименование толщин разрешено последующим уточнением UX-54 ниже. `PriceLM500` и `PriceHL` остаются read-only. Это уточнение относилось только к расширению существующих прайсов; последующее решение о формате прайсов новых станков приведено ниже.

В режиме редактирования «Добавить толщину» открывает компактные поля толщины и цены. «Добавить»/Enter подготавливает строку с отметкой «Новая», явное «Сохранить» применяет весь набор правок. Подготовленную строку можно убрать крестиком до сохранения; существующие толщины не удаляются. Незавершённый ввод тоже защищён при закрытии и блокирует сохранение остальных правок до добавления/отмены. Дубликаты проверяются численно: 2.8, 2,80 и 2,800 — одна толщина. Имя нового поля нормализуется в прежний вид `2,8`, целое 28 остаётся `28`. Новая цена обязательна, целая, 0…Int32.MaxValue. Существующие имена колонок не нормализуются заново.

В MDB новый столбец создаётся как nullable LONG и сразу заполняется ценой существующей единственной строки. `PriceTableChange` сохраняет старые колонки в прежнем порядке, новые добавляет в конец, максимум 255 полей с учётом служебных колонок. Тот же запрос операции 12 поддерживает расширение без перенумерации протокола; вычисляемые свойства HasAdditions/AddedRates в JSON не передаются.

Windows требует закрыть остальные подключения к MDB. Перед подключением Jet создаётся полная копия рядом с файлом: `OrderDB.mdb.before-price-expansion-UTC-guid.bak`, через временный `.partial` и запрет параллельного доступа при чтении. Неполная копия не становится резервной. Затем открывается исключительное соединение и проверяется полный снимок прайса. Резервная копия относится к моменту её чтения перед открытием Jet; автоматического восстановления/подмены рабочей MDB нет.

Все новые колонки и цены сохраняются в одной транзакции. Для Jet 4 Microsoft документирует поддержку DDL и DML в транзакциях ([свойство DBPROP_SUPPORTEDTXNDDL](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms714912(v=vs.85))), добавление столбца соответствует [Access SQL ALTER TABLE](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/alter-table-statement-microsoft-access-sql). Расширение в приложении разрешено только через Jet 4, как в поставляемом AccessHost x86: прямой другой провайдер получает NotSaved до копирования/DDL, пока его поведение отдельно не проверено. Обычное изменение цен сохраняет прежнюю поддержку провайдеров. Если запись после ALTER не удалась, выполняется rollback и отдельно проверяется возвращение исходных колонок/цен; неподтверждённый rollback/commit — OutcomeUnknown с запретом повтора. После успешного commit чтения нет.

F5 после конфликта/неясного исхода допускает появление новых столбцов, сохраняя исходные. Уже записанная новая толщина становится обычной строкой; незаписанная остаётся подготовленной. Чужие добавления и введённые пользователем цены сохраняются для явной проверки рядом с текущими значениями. Если уже применились все правки, повторное сохранение недоступно. Рабочую MDB не перезаписывают из резервной копии автоматически.

Linux-копия сохраняет новые элементы массива Rates в прежнем JSON-формате; MDB на Linux не меняется. В деморежиме новые тарифы живут только в памяти и не включают расчёт для создания демозаявок с неизвестной ценой.

В новом приложении тариф за новую положительную толщину сразу делает её доступной станку после перечитывания прайса. Старый код читает цены по имени столбца, но его ComboBox содержит фиксированный список толщин, а расчёт — прежние пределы: произвольные новые значения не объявляются уже доступными старому редактору. Это известная граница, согласованная пользователем для последующей доработки; проверка старого EXE на копии MDB и SMB остаётся отдельной.

## Новые станки в прежнем формате прайсов — решение 17.10.2026

**Подтверждено пользователем:** новые станки должны использовать тот же принцип хранения цен, что и старые. Ранее предложенная отдельная таблица тарифов с толщинами в строках не принимается. Для каждого нового прайса создаётся отдельная таблица в той же MDB, с одной строкой тарифов, служебным ключом по прежнему образцу и колонками толщин типа Long Integer. Дробные имена колонок записываются через запятую; последующие толщины добавляются тем же механизмом новых столбцов. NULL и настоящий нулевой тариф различаются. Таблицы/поля/ключи/значения прежних прайсов и Orders не преобразуются.

В UI толщины/цены по-прежнему отображаются вертикальными строками; представление не определяет физическую схему MDB. Новый прайс должен быть общим для всех клиентов этой MDB. Привязки новых станков хранятся в необязательном общем каталоге JournalMachines; старому EXE его читать не требуется. Формат самих прайсов остаётся прежним. Названия таблиц должны выбираться/проверяться приложением, не попадать в SQL напрямую из названия станка.

**Наблюдение по старому коду:** MainForm.cs в создании и редактировании выполняет SELECT нужной таблицы, читает первую строку и обращается к dbReader[thStr]; список станков Form1.Designer.cs и ветки выбора таблицы/диапазонов зашиты. Поэтому последующая доработка старой программы должна добавить пункт выбора, связь с новой таблицей, допустимые толщины и обе ветки расчёта/сохранения. Одного добавления таблицы или пункта списка недостаточно. При таком подходе обе программы смогут использовать один тариф без конвертации его хранения; это ещё требует проверки на копии MDB старым EXE и отдельно по сети.

**Текущий статус:** локально реализованы создание станка, общий каталог, отдельная таблица тарифов, выбор в обеих формах и расчёт за метр по толщине. В alpha.6 этого нет. Рабочая MDB не изменялась; нативный Windows-прогон/старый EXE/SMB остаются отдельными проверками.

Добавлены проверки `PriceExpansionTests`, UI для 960×700/840×560 обеих тем, нативные сценарии LONG/копии/исключительного доступа/отката DDL и расширение обязательного теста упакованного x86-хоста. Рабочая MDB и пользовательская Linux-копия при разработке не изменялись; PR/выпуск не создавались.

Финальный локальный прогон расширения: 788 тестов успешны, 15 частных/платформенных пропущены, 11 проверок выпуска успешны; Release без предупреждений/ошибок. 52 нативных Access-теста пропущены на Linux. Обе темы/размера с панелью добавления и новой строкой просмотрены, навыки валидны, `git diff --check` чистый. Это не прогон записи MDB/старого EXE/SMB на Windows.

### Создание станка и общий каталог — UX-47

«Прайсы → Добавить станок»: название, формат спецификаций (расширен 19.10.2026, см. раздел ниже), минимум одна толщина с целой неотрицательной ценой. Дробные толщины канонизируются с запятой; числовые дубликаты, пустые тарифы, служебные/старые имена отклоняются. Верхние пределы — 128 новых станков, 254 толщины на таблицу. Ввод только подготавливает строки; сохранение отдельное, закрытие с правками требует отказа. При записи закрытие дочернего/родительского/главного окна заблокировано. Старые группы и общий PriceLL500 для лазера/базового HansLaser сохраняются.

Необязательная таблица `[JournalMachines]`: `[Name] TEXT(255) NOT NULL UNIQUE`, `[PriceTableName] TEXT(64) NOT NULL PRIMARY KEY`, `[SpecificationProfileId] TEXT(64) NULL`. Прежняя MDB без неё читается как каталог без новых станков. Цена хранится в отдельной `[PriceMachine_<32 lowercase hex>]`: `[Код] COUNTER PRIMARY KEY`, столбцы толщин LONG, одна строка. Имя таблицы создаётся приложением, не из пользовательского названия. Текст станка записывается в прежнее Orders.Вид_резки; ключи/16 полей Orders не меняются. Переименования/удаления станка и удаление тарифных столбцов не предусмотрены; изменение толщин добавлено последующим этапом UX-54. Привязка профиля — только для импорта, не дополнительная формула. Расчёт новых станков: тариф × целые метры × редактируемый коэффициент, прежние Double/ToEven. Фиксированные диапазоны сняты по последующему уточнению 18.10.2026; доступность определяется тарифами.

Windows: снимок всего каталога, полная побайтовая резервная копия до открытия Jet, затем исключительное подключение, повторная проверка каталога и отсутствия таблицы, транзакция DDL + оба INSERT. Читаются все тарифы/привязки до commit. При откате отдельно проверяется восстановление схемы/каталога; непроверенный откат или ошибка после начала commit дают OutcomeUnknown. Автоповтора и автоматического восстановления MDB из копии нет. После неизвестного исхода форма блокирует запись до «Обновить»; если найден тот же станок со всеми введёнными тарифами, подтверждает уже выполненную операцию без INSERT. При подтверждённом отсутствии повтор использует прежнее безопасное имя таблицы. Добавление требует закрыть подключения остальных ПК. Backup использует прежний суффикс `.before-price-expansion-*.bak`.

AccessHost: протокол 1, новые операции ReadMachines=13 / CreateMachine=14; прежние номера сохранены. Клиент сверяет точный каталог/станок/все тарифы ответа. Создание/редактирование заявки повторно сверяет декларацию станка с текущим каталогом внутри транзакции; произвольный SQL/незарегистрированный прайс не допускаются. Диагностика не содержит названий/SQL/полей заявок.

Linux JSON v1 получил необязательный Machines; все старые файлы читаются без миграции. Прайсы новых станков добавляются к прежним шести Prices; сохранение каталога/тарифов атомарно в одном JSON. Импорт из MDB читает необязательный каталог и его прайсы. Обратной записи MDB нет. В деморежиме новые тарифы живут в памяти; прежние демозаявки без цены сохраняют прежнее поведение.

`Jornal.Inspect prices <MDB>` показывает новые привязки с именами таблиц и тарифами; `price <MDB> <название станка> ...` считает без записи. Это помогает последующей доработке старого EXE. Импорт ГАР — [отдельный контракт](waterjet-pdf-import.md). ## Редактирование существующих толщин — 18.10.2026, UX-54

Пользователь принял и поручил редактирование самой толщины с сохранением старого формата прайса. В режиме редактирования рядом с прежней толщиной находится поле новой, рядом с прежней ценой — поле новой цены. Подготовленные новые строки тоже исправляются. Все изменения остаются черновиком до сохранения; порядок не меняется при наборе. Числовые дубликаты и переход на уже существующую толщину блокируются, обмен/объединение толщин не поддерживаются. Равные значения вроде `2,5` / `2,50` не переименовывают поле. Отмена восстанавливает снимок.

Если меняется существующая толщина, первая команда сохранения не пишет данные. `IPriceImpactReader` сверяет исходный прайс и считает заявки прежних толщин по фактическому выбору таблицы: общий PriceLL500 включает лазер и базовый HansLaser, ID 1/2 имеют собственные счётчики, новые станки учитывают общий каталог. Оверлей показывает область действия, каждую пару толщин/цен и количество заявок. Исторические заявки не блокируют изменение, но явно сохраняют свою толщину/сумму; пересчёт без старого тарифа будет недоступен. «Вернуться»/Escape сохраняют ввод. «Добавить новые, сохранив прежние» подготавливает отдельные новые тарифы вместо переименования, без записи.

`PriceTableChange` сопоставляет прежние тарифы по исходным позициям, новые добавляет в конец; прямое удаление/перестановка не допускается. Для изменённой толщины требуется каноническое новое имя с запятой. `ConfirmedUsage` содержит подтверждённые счётчики по старым именам колонок. При окончательной записи источник повторно проверяет полный снимок и счётчики: новые заявки между предпросмотром и сохранением требуют повторного подтверждения. Исходный счётчик сам по себе не блокирует операцию. Orders и вспомогательные пометки не изменяются, исторические суммы не пересчитываются.

Windows: `JetPriceRenamer` использует системные ADODB/ADOX в одной COM-сессии Jet x86 и одной транзакции. Именно поле получает новое имя, без DROP/пересоздания и потери позиции/NULL/default/индексов; [свойство Name (ADOX)](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/name-property-adox), [поддержка Jet](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/provider-support-for-adox). Другие провайдеры для этой операции не включаются автоматически, Office/ACE и новые пакеты не устанавливаются.

До открытия пользовательской MDB каждый процесс проверяет доступность ADOX, переименование, commit и rollback на отдельной временной MDB. Если проверка не подтверждена, пользовательская база не открывается для изменений. Затем создаётся полная копия `*.before-price-edit-UTC-guid.bak`, открывается исключительное соединение, проверяются снимок прайса/каталог/счётчики. Переименования, новые столбцы и цены применяются вместе; новые цены — типизированные Integer-параметры. Проверка результата выполняется до commit; после него запросов нет. При неудаче откат проверяется по исходному прайсу. Неподтверждённый commit/rollback — OutcomeUnknown, повтор запрещён до явного перечитывания; копия не подменяет базу автоматически. Как и при расширении, копия отражает момент до открытия Jet, не произвольную последующую запись другого клиента.

Операция AccessHost `UpdatePriceTable = 12` сохранена; добавлена только read-only `ReadPriceUsage = 16`, необязательные поля протокола 1 не меняют прежние номера. Старый хост не получает обхода валидации. Клиент проверяет состав/числа/имена счётчиков и соответствие сохранённого прайса запросу. Linux MDB остаётся read-only, `.journal-test.json` и деморежим применяют тот же контракт атомарно. После конфликта переносится только изменённый ввод; применённое неподтверждённое переименование распознаётся при явном обновлении, без повторной записи. Произвольное исчезновение поля без известного черновика не угадывается.

Проверки включают подготовленные/существующие толщины, дубликаты/NULL/равные значения, общий прайс/ID/новые станки, предпросмотр без записи, изменение счётчиков/прайса другим клиентом, сохранение истории и потерю подтверждения, в том числе дальнейшую правку толщины до перечитывания. Headless проверяет обе темы и 840×560/960×700, клавиатуру/оверлей с длинным списком. Нативные тесты проверяют свойства/позиции/индексы, backup, исключительный доступ и откат после ошибки.
