# Journal — новый журнал заявок

Новый публичный репозиторий: [DenisPapushaJava/journal-v2.0](https://github.com/DenisPapushaJava/journal-v2.0). Исходная WinForms-версия и её история сохранены из [Jornal](https://github.com/DenisPapushaJava/Jornal); имена проектов `Jornal.*` пока сохранены для постепенного переноса.

Начальный проект на C# / .NET 10 LTS / Avalonia. Разработка ведётся на Linux, целевые рабочие места — Windows 10/11. Существующие база Access и форматы спецификаций сохраняются.

Сейчас приложение начинает с **трёх вымышленных заявок**: верхняя область результата, три группы команд, светлая/тёмная темы, таблица со строками 32 px и текстом 13 px. Работают поиск по выбранному полю, фильтры статуса и даты, обновление, множественный выбор, изменение ширины/порядка/видимости столбцов и высоты результата. Поиск остаётся в одной строке с фильтрами и сжимается при уменьшении окна.

**«Новая заявка»** открывает ручной ввод: реквизиты, параметры резки, коэффициент и дополнительные ID/газ для HansLaser. Ошибки отмечаются рядом с полями; дробные толщину и коэффициент можно вводить через точку или запятую. Добавленная заявка сразу выделяется, прежние фильтры сбрасываются для её показа. Она остаётся после F5, но хранится **только в памяти до закрытия программы**. Цена показана как «Не рассчитана»: прайсы ещё не подключены. Вес, размер и количество листов пока остаются текстовыми, как в существующей базе; импорт подсказок из конфигурации ещё не подключён.

Редактирование, запись статусов, работа с БЛЦБ и буфером, подготовка/копирование результата и персональная компоновка пока недоступны, но видны на привычных местах. Подключение к `OrderDB.mdb`, перенос расчётов и парсера, остальные формы и установщик — следующие этапы. Выбранная тема и компоновка пока действуют только в текущем сеансе. Клавиши: **Ctrl+F** — поиск, **Escape** в поиске — очистить текст, **F5** — обновить, **Shift/Ctrl** — выбор строк. В форме заявки **Enter** добавляет, **Escape** отменяет ввод.

Старая WinForms-версия остаётся в корне: `Jornal.sln`, `Jornal.csproj` и исходные файлы. Новая сборка — **`Jornal.Modern.slnx`**. При выполнении команд указывайте решение или проект явно.

UX-концепт подготовлен в Figma через Figwright: семь наборов экранов в двух темах и вторая итерация главного окна с верхним «Результатом», группами постоянных команд и вариантом 1366×768. Разбор старого интерфейса, карта функций, источники UX-решений и границы готовности — в [описании дизайна](docs/design/ux-concept.md). Перенесён каркас главного экрана и адаптирован эскиз ручной заявки под отдельное окно; остальные формы пока остаются макетами. Для иконок переиспользуются 15 SVG Lucide, шрифт Inter поставляется с приложением. SVG отображаются средствами Avalonia, дополнительные нативные библиотеки ради иконок не добавлены.

## Быстрый старт на Linux

Нужны Git, curl, Python 3 для проверки выпуска, графическая сессия и системные библиотеки для [Avalonia Desktop](https://docs.avaloniaui.net/docs/platform-specific-guides/linux). На этой машине SDK устанавливается в `~/.dotnet`; системные настройки и профиль оболочки не меняются. Скрипты находят SDK в PATH или этой папке.

```bash
./scripts/setup.sh
./scripts/dev.sh
```

Первый запуск setup скачивает закреплённый SDK из Microsoft, если он отсутствует, и восстанавливает пакеты из NuGet. После установки SDK повторный setup не скачивает его заново. Для первого восстановления нужен интернет.

```bash
./scripts/check.sh                # Release-сборка и тесты, без графической сессии
./scripts/publish.sh linux-x64     # artifacts/linux-x64
./scripts/publish.sh win-x64       # artifacts/win-x64
```

Публикация framework-dependent: среда исполнения не входит в эти папки. Для запуска нужен .NET 10 Runtime соответствующей ОС и разрядности. Это ещё не установщик. Будущий полный офлайн-установщик должен включать нужные зависимости и устанавливать их при необходимости.

По [FAQ Microsoft](https://code.visualstudio.com/docs/csharp/cs-dev-kit-faq), C# Dev Kit бесплатен для личных, учебных и открытых проектов, а также коммерческих команд до пяти разработчиков. У Avalonia есть бесплатные основные возможности и дополнительные функции по лицензии: [страница расширения](https://marketplace.visualstudio.com/items?itemName=AvaloniaTeam.vscode-avalonia). Для нашей начальной разработки платные инструменты не обязательны.

Уже задано в настройках:

- Новое решение `Jornal.Modern.slnx` выбрано для C# и Avalonia. Старое решение по умолчанию не загружается.
- Современный Roslyn, форматирование C#/AXAML при сохранении, оформление через `.editorconfig`.
- Вложение `MainWindow.axaml.cs` под `MainWindow.axaml`; сборочные папки скрыты, результаты сборки и `.local/` исключены из поиска и наблюдения за файлами.
- Предпросмотр открывается вручную, масштаб подгоняется под панель, лимит 15 кадров/с уменьшает нагрузку. Для просмотра выберите проект `Jornal.Desktop`.

| Действие | Команда VS Code |
| --- | --- |
| Собрать новое решение в Debug | **Ctrl+Shift+B**, задача `Jornal: build` |
| Запустить с отладчиком | **F5**, конфигурация `Jornal Desktop` |
| Запустить без отладчика | Tasks: Run Task → `Jornal: run` |
| Запустить тесты | Tasks: Run Test Task → `Jornal: test` |
| Собрать папку публикации Windows | Tasks: Run Task → `Jornal: publish Windows` |

Задачи на Linux используют `scripts/dotnet.sh`, на Windows — `dotnet` из PATH. Перед F5 автоматически выполняется Debug-сборка. Формат запуска отладчика `coreclr` поддерживается расширением C#.

На этой машине SDK установлен в `~/.dotnet`, профиль оболочки не изменён. Если VS Code, запущенный из меню, не найдёт SDK, полностью закройте все его окна и запустите из терминала в корне проекта:

```bash
export DOTNET_ROOT="$HOME/.dotnet"
export PATH="$DOTNET_ROOT:$PATH"
code .
```

Так среда SDK будет доступна и расширениям, и отладчику. Это окружение текущего процесса, не изменение системных настроек. При системной установке SDK через PATH эти команды не нужны. Путь к SDK не зашит в общие файлы `.vscode/`.

Проверены синтаксис JSON, задача Debug-сборки без предупреждений и запуск восьми тестов через задачу. Сам VS Code на момент настройки не найден в PATH; работу F5, панели тестов и предпросмотра внутри IDE ещё предстоит проверить после его установки.

## Разработка на Windows

Установите SDK, указанный в `global.json`. Из PowerShell в корне репозитория:

```powershell
dotnet restore Jornal.Modern.slnx --locked-mode
dotnet run --project src/Jornal.Desktop/Jornal.Desktop.csproj
dotnet build Jornal.Modern.slnx -c Release --no-restore
dotnet test tests/Jornal.Tests/Jornal.Tests.csproj -c Release --no-build --no-restore
dotnet publish src/Jornal.Desktop/Jornal.Desktop.csproj -c Release -r win-x64 --self-contained false -p:RestoreLockedMode=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/win-x64
```

`win-x64` — цель первой сборки интерфейса. Разрядность и способ работы будущего адаптера Access нужно проверить с установленным Office/драйвером; старый Jet x86 автоматически не становится доступным из процесса x64. Для проверки записи в MDB, совместного сетевого доступа и установщика потребуется Windows.

## Структура

| Проект | Назначение сейчас |
| --- | --- |
| `src/Jornal.Core` | Модель строки журнала, интерфейс чтения заявок, поиск. Без UI и драйверов. |
| `src/Jornal.Infrastructure` | Демонстрационный источник. Здесь будет адаптер к существующей Access. |
| `src/Jornal.Parsing` | Чтение структуры HTML через AngleSharp; слов и координат PDF через PdfPig. |
| `src/Jornal.Desktop` | Avalonia, Fluent, DataGrid, MVVM через CommunityToolkit. |
| `tests/Jornal.Tests` | Поиск, сохранение исходных значений, чтение структуры HTML, тесты окна Avalonia Headless. |
| `tools/Jornal.Inspect` | Консольная диагностика локальных HTML/PDF без записи в них. |

`DocumentReader` пока **не извлекает поля заявки** и не определяет станок, прайс или стоимость. Он сохраняет границы ячеек HTML, пробелы, признаки `@`/`*@`, страницы и координаты слов PDF. Извлечение полей, нормализация, расчёт и запись должны быть отдельными шагами. PDF без текстового слоя потребует отдельного решения для OCR.

Пример диагностики внешнего документа:

```bash
./scripts/dotnet.sh run --project tools/Jornal.Inspect/Jornal.Inspect.csproj -- "/путь/спецификация.html" "/путь/спецификация.pdf"
```

Команда выдаёт JSON с количеством таблиц, строк, страниц и слов. Это проверка чтения структуры, а не подтверждение правильного распознавания бизнес-полей. Файлы пользователя находятся вне Git; синтетические примеры для тестов создаются во временной папке.

## Правила разработки

- Одна задача — одна короткая ветка и PR в `main`; после успешного CI — squash merge с русским описанием и удаление ветки. [Порядок разработки](docs/development.md).
- Требования и матрица переноса сохранены в [локальном навыке](.agents/skills/jornal-modernization/SKILL.md). Перед переносом функции сверяйтесь с ним и старым кодом.
- Не изменять схему MDB и не пересчитывать историческую стоимость при чтении. Работу с реальной базой проверять на копии.
- В репозиторий не включать рабочую базу, настройки с сетевыми путями и реальные спецификации. Для локальных копий можно использовать игнорируемую папку `.local/`.
- SDK закреплён в `global.json`, версии пакетов — в `Directory.Packages.props`, точные зависимости — в `packages.lock.json` каждого проекта. Для осознанного обновления: изменить версию, выполнить `./scripts/dotnet.sh restore Jornal.Modern.slnx --force-evaluate`, проверить сборку/тесты и сохранить lock-файлы.
- CI в `.github/workflows/modern.yml` собирает новое решение и запускает Headless-тесты на Linux и Windows. Проверки драйвера Access, сетевых блокировок и установщика в этот CI пока не входят.

Парсеры подключены к диагностическому инструменту, но ещё не к окну журнала. Размер текущей публикации не является оценкой конечного установщика: в ней пока нет адаптера Access, парсеров и полного набора функций.

## Версии и выпуски

Схема **год.выпуск.исправление**: `2026.1.0`, `2026.1.1`, `2026.2.0`. Номер выпуска последовательный внутри года. Начальная версия разработки — `2026.1.0-dev`; предварительные выпуски получают суффиксы `alpha`, `beta` или `rc`.

CI проверяет новое решение на Linux и Windows. Тег вида `v2026.1.0-alpha.1` запускает сборку ZIP для обеих платформ с SHA-256 и создаёт черновик GitHub Release. Ручной запуск workflow `Release` проверяет упаковку без создания релиза. Порядок работы и текущие ограничения — в [инструкции выпусков](docs/releases.md).

## Проверено при настройке 15.10.2026

После добавления ручной формы: Release-сборка без предупреждений, 39 .NET-тестов и 5 проверок инструмента выпусков. В Skia Headless проверяются светлая/тёмная темы главного окна на 1280×720, 1366×768 и 1600×1000, размещение команд и однострочного поиска, фильтры, выбор, столбцы, клавиатура и сортировка. Ручная форма проверяется на 1060×600 и 1200×720 в обеих темах; покрыты создание, отмена, ошибки, повторная попытка, блокировка на время записи, сохранение полей и F5. PNG можно получить через `JOURNAL_SCREENSHOT_DIR="$PWD/.local/shell-preview" ./scripts/check.sh`. Это автоматические проверки UI; ручные сценарии Windows и совместимость MDB ими не подтверждаются.

На Linux Mint x64: Release-сборка без предупреждений, 8 тестов, обычный запуск окна и запуск опубликованного Linux-приложения. Повторный `setup.sh` работает без переустановки SDK. Структурное чтение прошло на всех 7 предоставленных HTML и 2 PDF; корректность полей заявки этим пока не проверяется. Контрольная сумма исходной MDB не изменилась.

| Начальная публикация до переноса каркаса UI | Размер файлов без сжатия |
| --- | --- |
| `artifacts/linux-x64` | 22,69 МиБ |
| `artifacts/win-x64` | 27,41 МиБ |

После переноса каркаса UI, добавления Inter и отображения SVG: около **27,4 МиБ для Linux** и **32,2 МиБ для Windows**, без Runtime. Размеры папок публикации измерены на Linux; это по-прежнему не полный установщик.

Это размеры демонстрационного UI без .NET Runtime. Из Release-публикации исключены PDB, в том числе примерно 100 МиБ нативных отладочных символов, приходящих с Windows-пакетами Skia/HarfBuzz. Сами библиотеки сохранены. Windows-публикация в таблице собрана на Linux. Текущие результаты сборки, тестов и упаковки на обеих ОС доступны в [GitHub Actions](https://github.com/DenisPapushaJava/journal-v2.0/actions). Ручная проверка рабочего интерфейса на Windows, совместной работы с MDB и установщика ещё предстоит.
