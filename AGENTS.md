# Journal

Новый публичный репозиторий — `DenisPapushaJava/journal-v2.0`, основная ветка `main`. Исходный `DenisPapushaJava/Jornal` сохраняется отдельно; при наличии remote `legacy` не отправлять туда изменения нового приложения. Имена существующих решений и проектов `Jornal.*` пока сохранены.

Пользователь выбрал версии **год.выпуск.исправление** (CalVer), например `2026.1.0`, затем `2026.1.1` или `2026.2.0`. Вторая часть — номер выпуска внутри года, не неделя. Правила CI, предварительных выпусков и черновиков релизов — в [docs/releases.md](docs/releases.md).

Сообщения новых коммитов, названия и описания PR, описание репозитория и заметки к релизам писать на русском языке. Имена API, файлов, зависимостей и другие технические идентификаторы сохранять в исходном виде.

Разработка: актуальная `main` → ветка на законченный этап → несколько локальных итераций и коммитов → один PR по готовности этапа → успешные обязательные проверки → squash merge. Не создавать PR на каждое сообщение, небольшую правку или коммит: связанные изменения накапливать в ветке этапа, проверяя локально через F5 и подходящие тесты. Ветку можно отправлять на GitHub для сохранности до открытия PR. Для веток Codex использовать `codex/`. После squash merge сохранять исходную ветку на GitHub с полной историей, не переписывать её и не продолжать в ней следующий этап. Завершение обозначает статус Merged у PR; `git branch --merged` после squash не является надёжной проверкой завершения. Автоматическое удаление веток отключено; не использовать `gh pr merge --delete-branch`. Следующий этап начинать от обновлённой `main`. Отдельные постоянные `develop` и ветки релизов не нужны; выпуски отмечаются тегами на `main`. Подробные команды — в [docs/development.md](docs/development.md). Слияние выполнять в рамках порученной реализации; запрос только на обсуждение или ревью сам по себе не поручает слияние.

Принято разделение CI: документация/настройки — соответствующие быстрые проверки; код — сборка и тесты Linux/Windows с обязательным Jet; установщик, обновления, Access-хост и упаковка — дополнительно полный цикл установки/обновления; перед релизом — полный набор. Это согласованное направление: текущий workflow пока запускает полный цикл на каждый PR и push в `main`. Перенастройку выполнить отдельным законченным этапом; не объявлять облегчённый CI уже реализованным. Защиту `main` и корректное завершение обязательных статусов сохранять.

При анализе, модернизации, изменении парсера, расчётов, интерфейса или доступа к данным этого проекта прочитай локальный навык [.agents/skills/jornal-modernization/SKILL.md](.agents/skills/jornal-modernization/SKILL.md).

В нём сохранены предварительные требования пользователя, исходное поведение приложения и сведения о предоставленных примерах. Используй их при продолжении работы в новых чатах. Новые уточнения пользователя имеют приоритет; обновляй соответствующий раздел навыка, сохраняя различие между требованием, наблюдением и предложением.

При работе над дизайном, UX, темами, плотностью таблицы, макетами Figma или переносом интерфейса в Avalonia также прочитай [.agents/skills/jornal-design/SKILL.md](.agents/skills/jornal-design/SKILL.md). Актуальные принятые решения и открытые предложения хранятся в его `references/decisions.md`; обновляй их при новых уточнениях пользователя.

Текущий этап — постепенная разработка нового приложения. Реализованы главное окно, темы, персональная компоновка, результат с HTML/RTF/текстом и чтение существующей MDB: Windows OLE DB, Linux MDB Tools. «База данных» выбирает источник и сохраняет проверенный путь отдельно от настроек экрана. Настоящая MDB читается с сохранёнными ценами и NULL; на Windows добавлены транзакционная запись статусов/БЛЦБ и проверка конфликтов. На Linux сама MDB остаётся только для чтения; отдельная тестовая `.journal-test.json` поддерживает реальные данные/шесть прайсов, создание с расчётом, статусы и БЛЦБ с сохранением между запусками. На Windows локальный режим недоступен, MDB-контракт сохраняется. Операции, ещё не перенесённые в новое приложение, не объявлять реализованными; обратной синхронизации в MDB нет. Описание — `docs/linux-local-copy.md`. Windows-пакеты включают хост x86 к системному Jet и полный OfflineSetup со средами .NET, без установки Office/ACE. Добавлены колокольчик, тихая проверка при запуске и раз в 6 часов до обнаружения новой версии, ручное обновление через Velopack/GitHub Releases; Setup.exe/AppImage и feed входят в черновики релизов, ZIP не обновляется. Выбор тестовых выпусков сохраняется в отдельном `update-settings.json`; установленная alpha/beta/rc при первом запуске включает тестовый канал, явный сохранённый выбор имеет приоритет. Автоприменение при запуске отключено; результат перед перезапуском сохраняется вне установки. Сценарий настоящего Windows-обновления проверяет отдельная `UpdateProbe` через `scripts/test-update-install.ps1`, рабочую MDB не использует. Добавлены отдельные чтение прайсов Windows/Linux и расчёт цены с прежними Double/ToEven; `Jornal.Inspect prices` / `price` проверяют их без записи. Протокол хоста расширен read-only операцией `ReadPriceTable`; прежние значения enum сохранены. Контракт — `docs/pricing.md`. На Windows добавлены создание с расчётом и предварительная цена в форме MDB: типизированный INSERT/AutoNumber в транзакции через хост x86, проверка изменения тарифа и неизвестного commit. Контракт и границы — `docs/manual-orders.md`. Полное редактирование, удаление, парсер и перенос старого конфига ещё предстоят. На копии предоставленной MDB выполнена сверка всех 16 полей и проверка окна на Linux; это не проверка сетевой записи на Windows. Ручное создание работает в `DemoOrderStore`, Linux `LocalJournalStore` и Windows `OleDbManualOrderCreator`/`AccessHostClient`; статусы и БЛЦБ — также через Windows `OleDbOrderBatchEditor`. Пакет принимает исходные записи, сохраняет только одно поле. Конфликт/неподтверждённый commit требуют успешного F5 перед новой записью. `tests/Jornal.Access.Tests` — отдельный обязательный контур Jet/ACE x86 в Windows CI, без изменения win-x64 поставки. Новое решение — `Jornal.Modern.slnx`, код в `src/`, проверки в `tests/`. Старый `Jornal.sln` и WinForms-исходники сохраняются для переноса поведения.

Команды Linux: `./scripts/setup.sh`, `./scripts/dev.sh`, `./scripts/check.sh`. SDK закреплён в `global.json`; скрипты также находят его в `~/.dotnet`. Для MDB на Linux нужен `mdb-export` из `mdbtools`; можно задать `JOURNAL_MDB_EXPORT`, `dev.sh` также подхватывает локальную `.local/tools/mdb-export`. Требования к поставке не считать выполненными наличием папки publish: полный Windows OfflineSetup добавлен с .NET x64/x86 и AccessHost x86 к системному Jet, Office не меняется. Сборка/ограничения — в `docs/windows-installer.md`. Чистый офлайн Windows 10/11 и общая папка требуют ручного прогона; создание новой заявки реализовано; полное редактирование ещё не реализовано. Не добавлять рабочую MDB и реальные спецификации в Git.

Полевой прогон Windows 11: в публичной alpha.2 собственные EXE не подписаны Authenticode, обнаружены отказ записи в Program Files и блокировка корневого launcher политикой Windows (CreateProcess 4551). Не объявлять, что сертификат автоматически снимет корпоративную политику; сначала смотреть CodeIntegrity/отчёт защитного ПО. Текущий установщик остаётся пользовательским и заранее объясняет ограничения защищённых папок. `scripts/Get-JournalDiagnostics.ps1` собирает локальный read-only отчёт без чтения MDB/изменения защиты; описание — `docs/windows-signing.md`. Пользователь выбрал направление MIT + SignPath, но приём сервиса/сертификат/подписанный выпуск ещё не получены; `docs/code-signing-policy.md` различает текущий статус и план. В окне колокольчика автопроверку можно отключить; настройка сохраняется, фоновые запрос/таймер отменяются, ручная проверка остаётся. Опубликованную alpha.2 новыми возможностями не наделять: они появятся только в следующем выпуске.
