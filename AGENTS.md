# Journal

Новый публичный репозиторий — `DenisPapushaJava/journal-v2.0`, основная ветка `main`. Исходный `DenisPapushaJava/Jornal` сохраняется отдельно; при наличии remote `legacy` не отправлять туда изменения нового приложения. Имена существующих решений и проектов `Jornal.*` пока сохранены.

Пользователь выбрал версии **год.выпуск.исправление** (CalVer), например `2026.1.0`, затем `2026.1.1` или `2026.2.0`. Вторая часть — номер выпуска внутри года, не неделя. Правила CI, предварительных выпусков и черновиков релизов — в [docs/releases.md](docs/releases.md).

Сообщения новых коммитов, названия и описания PR, описание репозитория и заметки к релизам писать на русском языке. Имена API, файлов, зависимостей и другие технические идентификаторы сохранять в исходном виде.

Разработка: актуальная `main` → короткая ветка на одну задачу → PR → успешный CI Linux/Windows → squash merge → удаление удалённой ветки. Для веток Codex использовать `codex/`. Отдельные постоянные `develop` и ветки релизов не нужны; выпуски отмечаются тегами на `main`. Подробные команды — в [docs/development.md](docs/development.md). Слияние выполнять в рамках порученной реализации; запрос только на обсуждение или ревью сам по себе не поручает слияние.

При анализе, модернизации, изменении парсера, расчётов, интерфейса или доступа к данным этого проекта прочитай локальный навык [.agents/skills/jornal-modernization/SKILL.md](.agents/skills/jornal-modernization/SKILL.md).

В нём сохранены предварительные требования пользователя, исходное поведение приложения и сведения о предоставленных примерах. Используй их при продолжении работы в новых чатах. Новые уточнения пользователя имеют приоритет; обновляй соответствующий раздел навыка, сохраняя различие между требованием, наблюдением и предложением.

При работе над дизайном, UX, темами, плотностью таблицы, макетами Figma или переносом интерфейса в Avalonia также прочитай [.agents/skills/jornal-design/SKILL.md](.agents/skills/jornal-design/SKILL.md). Актуальные принятые решения и открытые предложения хранятся в его `references/decisions.md`; обновляй их при новых уточнениях пользователя.

Текущий этап — постепенная разработка нового приложения. Реализованы главное окно, темы, персональная компоновка, результат с HTML/RTF/текстом и чтение существующей MDB: Windows OLE DB, Linux MDB Tools. «База данных» выбирает источник и сохраняет проверенный путь отдельно от настроек экрана. Настоящая MDB читается с сохранёнными ценами и NULL; на Windows добавлены транзакционная запись статусов/БЛЦБ и проверка конфликтов. Linux остаётся только для чтения. Windows-пакеты включают хост x86 к системному Jet и полный OfflineSetup со средами .NET, без установки Office/ACE. Добавлены колокольчик, тихая проверка при запуске и раз в 6 часов до обнаружения новой версии, ручное обновление через Velopack/GitHub Releases; Setup.exe/AppImage и feed входят в черновики релизов, ZIP не обновляется. Автоприменение при запуске отключено; результат перед перезапуском сохраняется вне установки. Сценарий настоящего Windows-обновления проверяет отдельная `UpdateProbe` через `scripts/test-update-install.ps1`, рабочую MDB не использует. Создание/редактирование заявок и расчёты ещё предстоит перенести. На копии предоставленной MDB выполнена сверка всех 16 полей и проверка окна на Linux; это не проверка сетевой записи на Windows. Ручное создание работает только в `DemoOrderStore`; статусы и БЛЦБ — также через Windows `OleDbOrderBatchEditor`. Пакет принимает исходные записи, сохраняет только одно поле. Конфликт/неподтверждённый commit требуют успешного F5 перед новой записью. `tests/Jornal.Access.Tests` — отдельный обязательный контур Jet/ACE x86 в Windows CI, без изменения win-x64 поставки. Новое решение — `Jornal.Modern.slnx`, код в `src/`, проверки в `tests/`. Старый `Jornal.sln` и WinForms-исходники сохраняются для переноса поведения.

Команды Linux: `./scripts/setup.sh`, `./scripts/dev.sh`, `./scripts/check.sh`. SDK закреплён в `global.json`; скрипты также находят его в `~/.dotnet`. Для MDB на Linux нужен `mdb-export` из `mdbtools`; можно задать `JOURNAL_MDB_EXPORT`, `dev.sh` также подхватывает локальную `.local/tools/mdb-export`. Требования к поставке не считать выполненными наличием папки publish: полный Windows OfflineSetup добавлен с .NET x64/x86 и AccessHost x86 к системному Jet, Office не меняется. Сборка/ограничения — в `docs/windows-installer.md`. Чистый офлайн Windows 10/11 и общая папка требуют ручного прогона; запись новых/полных заявок ещё не реализована. Не добавлять рабочую MDB и реальные спецификации в Git.
