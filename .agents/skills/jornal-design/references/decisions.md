### Исследование градиента и линзы на всю строку · 19.10.2026

Статус: исследование завершено последующим отказом от линзы/стекла в UX-75. Пользователь попросил посмотреть существующие компоненты и обсудить эффект линзы/градиент по всей выбранной строке. Это пока исследование, не замена принятого оформления приложения и не поручение менять смысл сохранённого ползунка.

Посмотрены первичные источники: [React Bits Glass Surface](https://reactbits.dev/components/glass-surface) (демо визуально проверено: выпуклый край, спокойный центр, параметры света/преломления), [rdev/liquid-glass-react](https://github.com/rdev/liquid-glass-react) с указанным автором [адресом демо](https://liquid-glass.maxrovensky.com/), [UI Layouts Liquid Glass](https://www.ui-layouts.com/components/liquid-glass). Веб-компоненты служат визуальными/техническими ориентирами, их установка или использование веб-движка в Avalonia не поручены. Код из них не копировался.

[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) относит Liquid Glass к слою управления/навигации и рекомендует не применять его к слою содержимого. Поэтому полноформатная линза в таблице не объявляется признанной практикой для данных; предложение для Journal — сдержанная стилизация фона выбранной строки.

Предложение: мягкий вертикальный градиент выбранного цвета (верх светлее, спокойная середина, нижняя полутень), широкий эллиптический блик и уже отдельный мягкий край каждой строки. Текст не искажать/не размывать/не увеличивать, столбец чекбоксов сохранять нейтральным; проверять контраст текста на всех участках градиента и при необходимости ограничивать силу света. База — прежний цвет/смысл выбора, без записи в MDB и с прежней геометрией. Настоящее преломление фона — отдельная сложность и проверка скорости, не обещать его по одному градиенту. Ползунок «Эффект стекла» для силы градиента/света/тени остаётся предложением; текущий RowHighlightStrength не переинтерпретируется без реализации миграции. На этом шаге производственный UI не менялся, push/PR/релиза нет.

## Контрастность наведения и выбора · UX-73, 18.10.2026

Предыдущее решение UX-73: **без обводок и боковых маркеров**; последующее UX-74 разрешает стеклянный контур каждой выбранной строки. Выбор показывается адаптивной заливкой и чекбоксом. Только служебный столбец выбора имеет нейтральный фон темы, одинаковый для любых цветов заявок; остальные ячейки показывают точный цвет из MDB в обычном состоянии, мягкое затемнение при наведении и более сильное при выборе (для очень тёмных отметок — осветление). Чекбоксы единые: мягкая серо-синяя рамка, скругление 3 px, синий выбранный фон и контрастная галочка, обычные hover/pressed. Они больше не зависят от яркости/цвета заявки. Не возвращать динамические чёрные/белые чекбоксы или маркеры у края строки.

«Общие → Журнал → Контрастность выделения»: ползунок с подписями Мягче — Контрастнее, живой предпросмотр двух оттенков/трёх состояний и компактный сброс. Сила 0–100/шаг 5, стандарт 50; минимум сохраняет заметность. Последнее решение пользователя возвращает основу WinForms: исходный цвет без смягчения, стандартный выбор RGB × 0,6 с усечением каналов, hover мягче, hover выбранной отдельный. Для очень тёмных цветов — осветление, чтобы не потерять видимость выбора. Строки без цвета в стандартном режиме выбираются DarkCyan (#008B8B) через отдельный JournalRowSelection. Пробный фон 58% отклонён пользователем; прежние варианты не восстанавливать. Ползунок меняет силу затемнения/осветления, а не обычный фон; защищённая разница состояний и численные параметры — docs/row-appearance.md, они не нормы WCAG. Значение ARGB в MDB не меняется. Контраст текста/галочки защищён отдельно. Старый обычный режим переносится в 50, повышенный в 100; явное новое значение приоритетнее.

По обратной связи о ширине и обрезании бегунка длина ползунка — 320 логических пикселей, слева; строка Auto вместо 32 px, сброс центрирован. Проверять фактический круг Thumb, минимальное/широкое окно и 100–200% DPI. Высоты строк 24–48, столбцы, выбор и клавиатура прежние. Настройка применяется сразу без запроса БД/Reset/потери контекста, сохраняется вне ScreenLayout/MDB. Сброс макета её не сбрасывает. RowAppearance общий для таблицы и предпросмотра, который тоже показывает нейтральный столбец и классические чекбоксы. Строка вернулась к штатному Fluent-шаблону, отдельная копия ради маркера не нужна. По следующему уточнению служебный столбец сужен до 24 px по последнему уточнению: квадрат 20 px и по 2 px отступа, CheckBox сохраняет область 24 px. Заголовок без лишних отступов, кнопка меню 24 px помещается целиком; защита ширины/замороженная позиция сохранены. Проверять центрирование/обрезание при 24 px и DPI 100–200%. Это заменяет прежнюю компоновку без изменения поиска. Весь запрос сравнивается с полем без регистра/крайних пробелов, внутренние пробелы/нули/знаки значимы. Обычный поиск по словам сохранён. Переключение применяет текущий ввод немедленно, включая debounce, со сбросом прежних фильтров/выбора; письмо/сортировка сохраняются. Смена конкретного поля сохраняет режим; «Все поля»/общий сброс выключают его. Крестик/Escape и F5 режим сохраняют. Только состояние сеанса, без MDB/новых настроек. Проверка компактной строки поиска обязательна в обеих темах и при масштабе 150%; контракт — docs/table-filters.md.

**Требование пользователя:** новый запрос должен находить заявки во всём журнале независимо от прежних фильтров, в том числе из пустого списка; среди найденного затем можно применять фильтры таблицы. Список полей сохранить для точного поиска БЛЦБ и других известных значений. Работа остаётся локальной, без push/PR/релиза.

**Выбранная реализация:** «Все поля», «Спецификация», «БЛЦБ», «Заказчик», «Менеджер», «Материал», «Комментарий». Вид резки/толщина/гибка уже имеют фильтры, даты — календарь; отдельные пункты числовых/служебных полей не добавлять. В «Все поля» дополнительно ищутся вид резки и точная толщина, без изменения исходных данных. В обычном поиске каждый термин должен встретиться, в общей области — в любом из поддержанных полей; лишние пробелы/регистр не меняют смысл запроса. В точном режиме значимы внутренние пробелы, см. уточнение выше. Конкретный состав списка и задержка выбраны при реализации, а не отдельным голосованием пользователя.

Новый текст/область сбрасывают дату/статус/пять фильтров, готовое письмо и сортировка сохраняются. Debounce 300 мс после последнего ввода; Enter и смена области — сразу. Крестик/Escape очищают текст и фильтры, сохраняя область; общий «Сбросить» возвращает также «Все поля». Во время ожидания снимается выбор и блокируются действия с прежним набором, поиск остаётся доступным. Программный сброс/закрытие отменяют таймер, отложенный запрос не восстанавливается. F5 обновляет полный снимок с сохранением текущего запроса/фильтров; незавершённый ввод сначала применяется как новый запрос.

Это поиск по полному загруженному снимку Orders, а не SQL-запрос на каждую букву; свежие изменения коллег требуют F5. Запрос готовится один раз, строки переиспользуются, список заменяется одним Reset с явным снятием нативного выбора. Контракт и границы — docs/table-filters.md. Схема MDB/письмо/настройки экрана не меняются. Проверки используют синтетические данные и Avalonia Headless, реальная Windows/сеть отдельно.

UX-57, принято пользователем и реализовано локально 18.10.2026: по центру верхней панели — местные часы и дата, например `14:38   Вс 18 октября`. Время и часовой пояс компьютера, русские сокращения дней с заглавной буквы и родительный падеж месяца из ru-RU независимо от языка ОС. Последнее уточнение пользователя: без запятых, время крупнее даты. Время — 18 px Medium, дата — 13 px Regular, одна базовая линия и небольшой промежуток; общий блок остаётся по центру. Секунды не показывать, лишние кнопки/настройки не добавлять. Шапка имеет равные боковые зоны: название/источник слева, прежние команды справа; длинный источник сокращается с прежней подсказкой, часы остаются точно по центру.

Компонент Controls/HeaderClock отделён от данных/компоновки журнала. Сразу обновляется при показе, затем на границе минуты; читает системное время заново, корректно переносит переход суток/года и скачок часов. Таймер останавливается при отсоединении/закрытии, не объявляет время как непрерывное уведомление и не получает фокус. Проверено: 24 связанные проверки окна/ширины/часов успешны на Linux, включая смену года, склонения, часовой пояс, остановку таймера, обе темы и размеры 1280/1366/1600. Снимки минимального окна обеих тем просмотрены. MDB/настройки экрана не меняются; без push/PR/релиза.

Уточнение пользователя UX-56, 18.10.2026: принят порядок **дата → числовой номер спецификации → код только при совпадении даты/номера**. Прежний второй критерий по коду заменён как неудобный. Прежний общий ASC уточнён UX-64: внутри дня — возрастание, ранние сверху: `859 → 900 → 909 → 920 → 1121`; внутри дня новые с более поздним номером встают ниже, а во всей истории более поздние даты/номера сверху; поздно импортированные ранние занимают своё место. Обычное нажатие «Даты» разворачивает все критерии; заголовок «Спецификация» также сравнивает численно. Ведущие нули равнозначны, номера не интерпретируются как время, исходный текст/даты не меняются. F5, создание/пакет/редактирование сохраняют текущую сортировку, включая явно выбранный другой столбец. Детали — docs/table-filters.md. Локально, без push/PR/релиза.

## Статусы

- **Принято пользователем** — явное требование или выбранный после обсуждения вариант.
- **Принято как основа** — составная часть показанного и одобренного макета; допускает развитие, не является неизменным ограничением на каждый пиксель.
- **Контракт совместимости** — наблюдаемое поведение старого кода, которое учитываем при сохранении функций; это не отдельное дизайнерское пожелание пользователя.
- **Предложено / нужно проверить** — ещё не утверждённая идея или непроверенное поведение реализации.

## Контракт совместимости и важные различия

Основание — статический разбор WinForms, описанный в [матрице функций](../../jornal-modernization/references/legacy-behavior.md), а не запуск старого EXE на Windows в этой сессии.

- В старом коде редактирование, удаление и обычный комментарий относятся к **активной строке**; БЛЦБ, Telegram-комментарий и папки используют выбранные строки. Новое уточнение пользователя 16.10.2026 расширяет удаление на все выбранные строки с общей формой подтверждения и итогом каждой операции (UX-22). По уточнению 17.10.2026 редактирование доступно только для одной выбранной заявки; прежний вариант с активной строкой внутри набора заменён UX-34.
- «Показать: В работе» фильтрует список; «Присвоить статус: В работе» меняет выбранные записи. Области нужно различать.
- «Снять цвет» очищает сохранённую цветовую отметку, а не выбор строк. Произвольный цвет не следует автоматически объявлять стандартным статусом. Код цвета должен оставаться доступным.
- «Результат» формируется заново по текущим выбранным заявкам и заменяет прежний текст (уточнение пользователя 17.10.2026, UX-28). Его очистка не означает снятие выбора строк.
- Старое копирование результата помещает в буфер **Unicode-текст и RTF**. 16.10.2026 пользователь разрешил улучшить подготовку текста для вставки в почту; в приложении дополнительно публикуется HTML с выравниванием по ячейкам. Уточнение 17.10.2026 (UX-27): начальные Arial 10 pt и мягкий красный, выбранные цвет/размер передаются в HTML/RTF и не зависят от темы окна. Внешний вид окна не должен испортить читаемость письма при вставке, особенно при тёмной теме. Сохранять структуру текста и проверять её отдельно от макета; минимум цены письма не менять под видом оформления. По явному уточнению UX-39 он теперь настраивается пользователем, стандартное значение — 500 ₽.
- Telegram-комментарий копирует текст; существующее действие не отправляет сообщение. Автоматическая отправка почты также не входит в согласованный дизайн.

## Персональная компоновка — принятая основа UX-08

15.10.2026 пользователь явно принял перечисленный ниже сценарий словами «давай так пока ориентироваться». 16.10.2026 пользователь поручил реализовать режим. Первая версия добавлена в приложение; снимок Figma остаётся прежним.

Принятый сценарий:

1. Компактная иконка **«Настроить экран»** рядом с настройками включает режим редактирования компоновки (уточнение оформления — UX-09).
2. Появляются рамки и места захвата: можно переставлять блоки, менять высоту **«Результата»**, размеры панелей и ширину столбцов.
3. Элементы привязываются к понятным зонам и имеют минимальные размеры, чтобы сохранялись читаемость и видимость команд.
4. **«Готово»** сохраняет компоновку, **«Отмена»** возвращает вариант до входа в режим.
5. **«Сбросить к макету»** показывает стандартный вариант. До нажатия **«Готово»** этот сброс тоже можно отменить.

Решения первой реализации 16.10.2026, не отдельные подтверждённые требования пользователя:

- Перестановка групп доступна только в режиме настройки; столбцы и высоту результата можно менять и в обычном режиме. Во время редактирования команды работы с заявками, фильтры и выбор строк приостановлены. Иконка сопровождается подсказкой и доступным названием, чтобы его не путали с редактированием заявки.
- Перемещаются три группы команд (обмен местами) и результат (над/под группами). Поиск остаётся над таблицей. Высота результата первоначально 120–280 px, по UX-27 — 106–280 px; минимальные ширины групп: заявки 312, буфер 430, статус 428 px. Это границы первой реализации. UX-03 сохраняет верхнее положение результата в стандартном варианте.
- Сброс восстанавливает стандартные положения, размеры панелей и параметры расположения столбцов, входящие в этот режим. Он не очищает результат, не меняет заявки, цены, поиск/фильтры, тему, путь к базе или другие независимые настройки.
- Стандарт — встроенная компоновка текущей версии приложения, по последнему принятому решению (с 17.10.2026 — UX-40, снимок Figma v2.1 старее реализации). Для сброса не нужно подключаться к Figma. Макет остаётся исходным вариантом при отсутствии личных настроек.
- Личная компоновка хранится отдельно для пользователя ОС, в локальном файле настроек, без изменения общей `OrderDB.mdb` и без влияния на коллег. JSON-профиль `Journal/ui-settings.json` находится в LocalApplicationData Windows / ApplicationData Linux. Экспорт и импорт профиля через интерфейс пока не добавлены.
- Реализованы устойчивые идентификаторы, порядок/зона/веса ширин, версия профиля и восстановление новых элементов по умолчанию. Повреждённый/несовместимый файл приводит к стандартному экрану и сообщению; без пользовательских изменений файл не перезаписывается. Запись идёт через временный файл с заменой; при отказе «Готово» оставляет режим открытым. Тема сохраняется независимо от черновика; закрытие окна отменяет несохранённую компоновку.

Для изменения ширины используется `GridSplitter`, перемещение блоков реализовано внутренними захватами указателя с подсветкой зоны и альтернативой на стрелках клавиатуры. Действия снабжены подсказками и доступными именами. Техническая основа: [drag-and-drop](https://docs.avaloniaui.net/docs/input-interaction/drag-and-drop) и [GridSplitter](https://docs.avaloniaui.net/controls/layout/panels/gridsplitter) в Avalonia; правила размещения, сохранение и восстановление реализованы в `Customization/MainWindowCustomization.cs`. Универсальный конструктор произвольных элементов не входит в эту версию. Сходный пользовательский паттерн есть в [Microsoft Business Central](https://learn.microsoft.com/en-us/dynamics365/business-central/ui-personalization-user): отдельный режим персонализации, перемещение и возврат к стандартному виду. Возможности скрывать команды из этого примера не переносятся автоматически в Jornal.
