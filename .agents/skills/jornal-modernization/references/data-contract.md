# Совместимость Access и настроек

## Режим эксплуатации

Пользователь подтвердил общую папку на одном компьютере и сетевой доступ клиентов. Windows 10 и 11 обязательны. Сохранить один существующий `OrderDB.mdb` и совместимость с прежними данными; чтение временной экспортированной копии не заменяет такую совместимость.

Использовать Windows-доступ через совместимый драйвер Microsoft как исходный вариант для сетевой записи. Старое приложение — .NET Framework 4.8, x86, `Microsoft.Jet.OLEDB.4.0`. Первый адаптер чтения нового приложения выбирает зарегистрированный ACE 16/12 текущей разрядности, Jet 4 допускается только в x86. Поставка пока win-x64; выбор окончательной разрядности, установка драйвера и возможный вспомогательный процесс для Office x86 ещё не утверждены. Не считать Access автоматически кроссплатформенным из-за кроссплатформенного UI.

## Первый этап интеграции — только чтение, 16.10.2026

Пользователь поручил максимально ориентироваться на предоставленную настоящую `OrderDB.mdb`. `AccessOrderReader` загружает `Orders` по именам колонок и проверяет все 16 ожидаемых полей, включая пустую таблицу. Windows использует `System.Data.OleDb`, соединение `Read|Share Deny None`, отключённое удержание в пуле и `SELECT`; Linux запускает `mdb-export` без shell. Выгрузка обрабатывается структурно, включая кавычки, переносы, Unicode, настоящий NULL и текст `"NULL"`. Чтение/открытие файла выполняется вне потока UI; неполный результат не подменяет прежний список. Для Linux это средство проверки и просмотра, а не транзакционная копия сетевой MDB при параллельной записи.

Дата и её исходное время, неизвестные толщина/цвет/длина/цена не подменяются нулём или сегодняшней датой. В read-модели дата отображается как DateOnly, исходное DateTime сохраняется отдельно. Пустые текстовые поля отображаются пустыми; это модель просмотра, а не готовая модель полной перезаписи записи. Исходная строка коэффициента сохраняется вместе с осторожно разобранными вспомогательными значениями; неизвестное значение не объявляется коэффициентом 1. Прайсы при чтении не используются. Список упорядочен по дате и затем ID по убыванию; это решение нового UI, не новое бизнес-правило.

Источник выбирается через «База данных» и хранится в локальном `Journal/data-source.json` отдельно от `ui-settings.json`. Путь сохраняется после успешной загрузки. Ошибка чтения или сохранения настроек оставляет прежний источник, список, выбор и результат. Ошибка при запуске с сохранённым путём не переключает приложение молча на демоданные. При настоящей смене источника очищаются результат, выбор и фильтры. MDB-доступ не реализует интерфейсы создания/массового изменения, поэтому эти команды недоступны; демохранилище остаётся отдельным режимом.

На Linux выполнены повторное чтение копии предоставленной базы, независимая сверка всех 16 полей с выгрузкой и проверка окна в обеих темах. Хеш оригинала и копии не изменился; частные результаты остаются в `.local/private-references/`. Проверка этого небольшого образца не доказывает производительность большой сетевой базы. Искусственный список из 5000 строк проверяет поиск и виртуализацию UI. В Windows CI предусмотрено создание искусственной Jet MDB через установленный ACE и отдельный тест типов/NULL/неизменности байтов; при отсутствии драйвера он явно пропускается. Ни эта проверка, ни сборка Windows не заменяет испытания реальной общей папки, Office-разрядности и старого EXE. Запись в MDB, прайсы, перенос конфига и установщик ещё не подключены.

При реализации учитывать блокировки Access, короткие транзакции, освобождение соединений, конфликт изменений и потерю связи. Проверка исходных значений при `UPDATE` может обнаруживать конфликт без добавления поля версии. Старая программа с безусловными обновлениями всё равно может перезаписывать чужие изменения; не обещать полную защиту без проверки всех писателей.

Прямую совместную запись через Jackcess не принимать за эквивалент Jet/ACE: библиотека не обеспечивает совместимость транзакций/блокировок с параллельными писателями. Иной способ доступа требует отдельной проверки именно сетевого многопользовательского сценария.

## Структура существующей базы

Схема исследована на копии предоставленного файла. Рабочая MDB и конфигурация не публикуются. Частные пути, хеш образца и точные результаты исследования сохранены локально в `.local/private-references/data-contract.md`; этот файл может отсутствовать после клонирования репозитория.

### `Orders`

Поля перечислены по выгруженной схеме. Старый UI использует числовые индексы колонок; не переносить зависимость от их порядка, работать по именам.

| Поле | Тип Access / назначение |
| --- | --- |
| Код | AutoNumber / Long Integer, первичный ключ |
| Дата | DateTime, дата из заголовка спецификации |
| Менеджер | Text(255) |
| Спецификация | Text(255), старое представление `MMDD-номер` |
| Заказчик | Text(255) |
| Вид_резки | Text(255) |
| Марка_стали | Text(255), фактически произвольный материал |
| Размер_листа | Text(255), например `1500x6000` |
| Кол_во_листов | Text(255), несмотря на числовой смысл |
| Стоимость | Currency |
| Толщина | Double |
| Ход | Long Integer, длина в метрах после старого округления |
| Вес | Text(255), встречается десятичная точка |
| БЛЦБ | Text(255), номер реализации, может отсутствовать |
| Color | Long Integer, ARGB, default `-1` |
| Коэффициент | Text(255), составное/старое значение, возможен NULL; в схеме default `1` |

Поля `Стоимость`, `Толщина`, `Ход` имеют в исследованной схеме default `0`. Существующие значения и NULL учитывать независимо от defaults новых записей.

### Статусы и составной коэффициент

| Смысл | Значение `Color` |
| --- | --- |
| В работе | `-882036` |
| Готово | `-10238087` |
| Отгружено | `-8154114` |
| Без назначенного цвета | `-1` |

Допускаются любые пользовательские ARGB-цвета. В присланном конфиге начальный цвет `-16711936`; это не один из трёх фиксированных статусов.

Старый код читает формы коэффициента `коэффициент|детали|пробивки` и `коэффициент|детали|пробивки|ID|газ`. Поддержать также NULL/пустое и старое одиночное число. При создании из ручного ввода составные данные могут быть неполными; заранее не считать все записи пятичастными. Значения `-1` используются как отсутствие вспомогательных сведений. В HansLaser-строках вокруг `|` могут быть пробелы.

Внутри новой модели это могут быть отдельные поля; адаптер отвечает за совместимое чтение/запись. Не переписывать старые строки только при просмотре.

### Прайсы

`PriceLM500`, `PriceLL500`, `PriceP`, `PriceG`, `PriceHL_id1`, `PriceHL_id2`. Имена колонок — толщины, в том числе `0,5`, `0,8`, `1,2`, `1,5`, `2,5`; значения — Long Integer. Старый код читает первую строку. Доступность тарифа и диапазон допустимой толщины в коде — разные ограничения.

В исследовании обнаружены исторические суммы, отличающиеся от расчёта по текущему прайсу при пустом коэффициенте. Причина не установлена: это могут быть прежние тарифы или исторические правила. NULL не объявлять коэффициентом 1 автоматически; не пересчитывать сохранённые суммы при просмотре. Точные значения остаются в частных локальных заметках.

## Конфигурация

- `connectionStrings/pathdb`: строка OLE DB с путём к существующей MDB. Путь может указывать на Release даже при предоставлении конфигурации из Debug; это не доказательство ошибки.
- `appSettings/Managers`: список подсказок менеджеров через запятую.
- `appSettings/Customers`: список подсказок заказчиков через запятую.
- `appSettings/TechnologColor`: начальный цвет новой заявки.

Поддержать перенос этих настроек и настройку пути к общей базе. Полный Access/Office как пользовательский интерфейс не является функцией приложения; необходимые драйверы и их установку проверить отдельно.

Пользователь подтвердил единый установщик со всеми необходимыми компонентами; подробности поставки находятся в разделе «Выбранная технология и поставка» файла [requirements.md](requirements.md). Учитывать существующий Office и разрядность его компонентов при выборе драйвера. Сетевой путь и возможность чтения базы проверять без тестовой записи в рабочие данные. Установка и обновление сохраняют существующие MDB и настройки.

## Граница работ с данными

Для исследования, проверки миграции кода и тестовой записи работать с копией. Исходные файлы пользователя не включать в публичный репозиторий автоматически. Любое будущее изменение схемы, замена СУБД, синхронизируемая вторая база или хранение новых полей требует отдельного решения в рамках конкретной задачи.
