# Контрольные образцы спецификаций

Исследованы 15.10.2026: семь HTML БЛОК/Wintech и два текстовых PDF HansLaser. Структурный читатель прочитал предоставленные файлы; извлечение бизнес-полей и полное сравнение со старой программой ещё предстоит реализовать.

Реальные спецификации, точная опись файлов, частные пути и извлечённые значения не публикуются. В текущем рабочем окружении они сохранены в `.local/private-references/samples.md`. На новом компьютере этот игнорируемый файл и сами образцы могут отсутствовать; для проверки на реальных данных нужно получить их отдельно у пользователя. В Git хранятся только синтетические проверки чтения документов.

## Что покрывают образцы

- Изменение HTML-разметки и расширения имени заказа внутри заголовка без изменения его смысла.
- Отличие даты печати отчёта от даты заказа в заголовке; использовать дату заказа.
- Длинные имена заказов и деталей, переносы, служебные символы внутри названий.
- Одинарные и двойные дефисы в заголовке, десятичные точки и запятые, лишние пробелы в имени файла.
- Произвольные материалы без пробелов, смешение кириллицы и латиницы; не менять алфавит марки молча.
- Длительность свыше суток и вариант с секундами. Длительность не является временем суток.
- Итоговые количества деталей и пробивок, длина реза и вес должны браться из итогового раздела, а не из случайной строки детали.
- В HansLaser проверять суффикс ID материала и связанный газ по существующему правилу; текстовым предоставленным PDF не требовался OCR.

Служебные признаки станка, источники номера/даты и правила округления описаны в [legacy-behavior.md](legacy-behavior.md), требования пользователя — в [requirements.md](requirements.md). Поддержка предоставленных вариантов не означает, что уже проверены все возможные версии отчётов.

Контракт/ограничения — [docs/specification-import.md](../../../../docs/specification-import.md). Заполнение формы по частному корпусу дополнительно сверяется без записи; HTML-импорт и перетаскивание подключены в UX-24. PDF HansLaser и текстовый ввод остаются следующими этапами.

## Дополнительные PDF HansLaser, исследование 17.10.2026

Пользователь предоставил новую папку с 60 PDF: 56 одностраничных, три двухстраничных и один четырёхстраничный, всего 66 страниц. Все содержат текстовый слой; структурный `DocumentReader` нового решения прочитал 60/60 без ошибок (66 страниц, 22 618 слов). Независимое извлечение Poppler также прошло без ошибок, по текстовым выгрузкам отдельно собраны наблюдаемые поля шапки и таблиц листов. Визуально просмотрены шесть страниц пяти характерных документов. Это исследование входного формата, не проверка готового HansLaser-парсера или записи в MDB: такого профиля ещё нет.

Наблюдения по предоставленному набору:

- Отчёты имеют общий шаблон Crystal: верхний блок «Заказ»/итоги, таблица «Листы», затем «Детали»; продолжения страниц содержат детализацию и повторяющиеся заголовки/примечания.
- Во всех документах виден начальный `@` перед датой формирования отчёта. В восьми дата формирования отличается от даты идентификатора в поле «Заказ»; номер/дату заявки необходимо по прежнему требованию брать именно из этого поля. Есть одинарный и двойной дефис перед номером.
- Есть 13 различных исходных названий материала с суффиксами `_0`/`_1`/`_2`, газы O2/N2, 17 вариантов целой толщины от 3 до 60 мм. Внутри каждой спецификации материал, газ и толщина по строкам листов согласованы. Это наблюдение корпуса, не ограничение допустимых марок/газов будущего профиля.
- В трёх документах по два размера листа; повторяющиеся размеры и строки раскладок не равны общему количеству листов. Колонка «К-во» содержит повторяемость раскладки, общий итог «Листов» — число физических листов. По независимой текстовой выгрузке суммы количеств совпали с шапкой во всех 60 документах; для нового профиля нужна отдельная автоматическая сверка.
- В двух документах значение колонки «№» — `1, 1`, при этом «К-во» и общий итог равны 1. Это исходный текст PDF, подтверждённый просмотром одного такого документа, не дробное количество листов и не основание считать два листа.
- Длительность доходит до 342 часов; часы нельзя разбирать как время суток. Есть длинные имена деталей и переносы, смешанная кириллица/латиница, несколько страниц.

Предложение следующего этапа: отдельный профиль `hans-pdf/v1` на координатах слов/границах разделов и заголовках колонок, без фиксированных индексов строк. Итоги брать из верхнего блока, габариты/материал/ID/газ — из таблицы листов; детали не подменяют итоги. Нормализация HansLaser должна сохранить прежний Ceiling для длины и общий расчёт коэффициента, не использовать правило метров БЛОК. Смешанные материалы/толщины/газы, повреждённый текстовый слой и сканы этим корпусом не проверены. Профиль, его подключение к форме и тестовый корпус ожидаемых нормализованных заявок ещё не реализованы.

Точная опись, хеши, исходные поля и примеры находятся в игнорируемых `.local/private-references/samples.md` и `.local/hans-analysis/`. SHA-256 всех 60 исходников после исследования совпали; MDB не открывалась и не изменялась. Реальные PDF и извлечённые данные не добавлять в Git.

## Подключение HansLaser-профиля, 17.10.2026

После исследования пользователь поручил реализацию. `hans-pdf/v1` и `HansSpecificationNormalizer` подключены к CLI `hans-spec` и общей форме импорта HTML/PDF. Предыдущее состояние «профиля ещё нет» выше описывает только момент исследования. Частный корпус 60 PDF сверяется с независимо подготовленными полями Poppler, исходными длиной/весом/длительностью, количеством раскладок и хешами; отдельный тест проверяет заполнение формы без записи. Публичные случаи — синтетические PDF/координаты, без реальных документов в Git. Числа количества берутся из «К-во»/«Листов», марки с дополнительными `_` сохраняются при выделении последнего подтверждённого ID. Источники включают страницу/прямоугольник/исходный текст. Подробный контракт и ещё не выполненные Windows-сценарии — `docs/hans-pdf-import.md`.
